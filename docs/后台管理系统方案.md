# 软硬件一体化后台管理系统 · 技术方案（一期网页端 / 二期小程序端）

> 目标：一套能管「软件产品 + 硬件设备 + 用户 + 授权 + 支付 + 收入 + API 消费」的后台，
> 前端纯静态，数据落 SQLite，单进程可跑，后续可平滑换 MySQL/PostgreSQL。

---

## 一、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 22（Fastify） | 启动快、体积小、插件体系适合做模块化路由 |
| 数据库 | SQLite（better-sqlite3）+ WAL | 零运维、单文件备份；ORM 用轻量手写 SQL + 迁移脚本，后期可切 MySQL |
| 前端 | 纯静态（原生 ES Module + Vue 3 全局构建版 + Tailwind CDN） | 无构建、无需 npm 打包，改完刷新即生效；管理端组件自研一套轻量 UI |
| 认证 | JWT（管理员）+ 微信 OpenID 会话（C 端用户） | 两套体系互不干扰 |
| 支付 | 微信支付 v3（Native 扫码 / JSAPI）、支付宝 当面付 & 电脑网站支付 | 均在服务端签名，回调落库 |
| 微信 | 服务号：网页授权 + 扫码登录（带参数二维码）+ 模板消息 | 一期网页端扫码登录 |
| 物联网 | ThingsBoard REST API  proxies | 用户 OpenID → TB 账户的自动映射与开通 |
| 部署 | `node server.js` 单进程 + systemd / pm2；静态资源同源托管 | 一台 2C4G 机器即可 |

**目录结构**

```
/
├─ server/                 # 后端
│  ├─ index.js             # 入口
│  ├─ db/                  # 迁移 + 种子数据
│  ├─ routes/              # admin / user / product / order / pay / wechat / tb
│  ├─ services/            # 业务逻辑（license、points、tb、pay）
│  └─ lib/                 # jwt、wechat-sdk、wxpay-v3、alipay、upload
├─ public/                 # 纯静态前端
│  ├─ admin/               # 管理后台（SPA）
│  ├─ user/                # 用户个人空间（SPA）
│  └─ assets/
├─ data/                   # app.db、上传文件、日志
└─ docs/
```

## 二、核心数据模型（一期）

```
users              用户：openid/unionid、手机号、积分、状态、TB 账户
tb_accounts        TB 映射：username(openid@tb.cn)、pwd、tenant/customer id
products           产品（软件/硬件/服务）：类型、价格、图标、简介、上架状态
product_versions   版本：版本号、包体、更新日志、下载量
licenses           授权：用户+产品+license_key+设备上限+有效期+状态
license_devices    授权绑定的设备（TB device id / 机器码）
devices            硬件台账：SN、型号、归属用户、TB 设备凭证、在线状态
orders             订单：订单号、用户、金额、渠道、状态、关联授权/产品
payments           支付流水：渠道交易号、回调原始数据、对账标记
points_logs        积分流水：来源、变动、余额
stats_daily        日粒度统计：下载数、安装数、活跃数、新增用户、收入
api_usage          API 调用明细：用户、接口、次数、计费额度
settings           站点配置：站点名、Logo、备案号、联系方式、主题色
admins / roles     管理员与角色权限
wechat_config      服务号配置：AppID/Secret/Token/AESKey/模板ID
pay_config         微信支付/支付宝商户参数（敏感值加密存储）
```

**ThingsBoard 映射规则（按你的要求固定）**

- 用户 OpenID `123abc` → TB 账户 `123abc@tb.cn`，密码 = `123abc`（OpenID 本身）
- 开通时机：用户首次微信扫码登录 / 首次购买硬件时，服务端用 TB 系统管理员 Token 调用
  `POST /api/user` 创建 TB User（挂到指定 Customer），失败进重试队列并告警
- 授权硬件时同步在 TB 侧创建/认领 Device，并把凭证写回 `devices` 表

## 三、功能模块

### A. 管理后台（admin）

1. **仪表盘**：今日/累计下载安装、活跃用户、收入、API 消耗、待办（待发货授权、待处理订单）
2. **产品管理**：软件/硬件 CRUD、版本发布、上下架、图标与截图、下载量与活跃数图表
3. **授权管理**：发放/续期/吊销授权、绑定设备数上限、License Key 生成与导出
4. **订单与收入**：订单列表、退款、收入趋势、渠道占比（微信/支付宝）
5. **API 消费**：按用户/接口统计调用量、额度包售卖与扣减
6. **用户管理**：列表、详情（账号/手机/积分/硬件/订单/授权）、禁用、手动加积分
7. **官方上架产品栏目**：我方软硬件产品的展示位管理（首页推荐位、排序、Banner）
8. **站点设置**：站点名称、Logo、Favicon、备案号、版权、主题色、联系方式 —— 管理员改完即时生效
9. **接入配置**：微信服务号参数、微信支付、支付宝、ThingsBoard 地址与管理员账号（表单化配置，不明文回显密钥）
10. **管理员与角色**：多管理员、角色权限

### B. 用户端（user，网页版）

1. **微信扫码登录**（服务号带参二维码 / 网页授权）+ **手机绑定**（短信验证码）
2. **个人空间**：我的软件、我的硬件（含 TB 设备在线状态）、我的授权、我的订单、积分明细
3. **官方商城**：浏览我方上架的软硬件产品 → 下单 → 微信/支付宝支付 → 自动发放授权/发货
4. **积分**：签到/购买/活动获得，兑换抵扣

### C. 二期（微信小程序端）

- 小程序登录（code2session 与 OpenID 打通）、商品浏览、下单支付（小程序支付）、
  我的设备（对接 TB 实时数据）、扫码绑定硬件。后端 API 一期已按「同一套接口、多端鉴权」设计，二期只做前端。

## 四、关键流程

**微信扫码登录**：后端生成带 scene 的临时二维码 → 用户扫码 → 微信推送事件 → 后端据 OpenID 建/取用户 → 前端轮询拿到 JWT。

**购买 → 授权**：下单 → 支付（微信/支付宝）→ 异步回调验签 → 订单置为已支付 →
生成 License Key → 若是硬件则创建 TB 设备并绑定 → 站内通知（模板消息/站内信）。

**授权校验（对外 API）**：客户端携带 License Key + 设备指纹 → 校验有效期/设备数 → 记 `api_usage` → 返回结果。

## 六、需要你确认的事项

1. 微信服务号：是否**已认证**（网页授权、模板消息、扫码登录需认证服务号/订阅号受限）
2. 微信支付 & 支付宝：是否已有**商户号/APPID**（无则先用「模拟支付」开关跑通流程，后续填参数即用）
3. ThingsBoard：部署地址 + 系统管理员账号（用于自动开户），以及用户应挂在哪个 Tenant/Customer 下
4. 域名与服务器：是否已有备案域名与 HTTPS（微信回调强制要求 HTTPS）
