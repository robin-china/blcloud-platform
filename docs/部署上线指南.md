# 部署上线指南

## 零、你的环境：Ubuntu 22.04 + 认证服务号 + 微信支付（无支付宝）

**部署形态：子路径** —— 挂在 `www.bliot.cn/platform/` 下，与现有官网共存。

选它的原因：`www.bliot.cn` 是**商业证书**，加子域名要另外花钱；而官网是纯静态站，加一段 `location` 就行，冲突最小。

```bash
# 后端加一个环境变量即可（PM2 在 ecosystem.config.cjs，systemd 在 blcloud.service）
BASE_PATH=platform

# Nginx 用现成的：deploy/nginx-subpath.conf
#   推荐把里面那段 location /platform/ 直接加进官网现有 server 块，共用同一份证书
#   注意 proxy_pass 末尾不要带 / ，否则 nginx 会剥掉 /platform 前缀，后端就 404

# 访问地址
管理后台  https://www.bliot.cn/platform/admin/
用户中心  https://www.bliot.cn/platform/user/

# 微信服务号后台
服务器地址(URL)   https://www.bliot.cn/platform/api/wechat/server
网页授权域名      www.bliot.cn          ← 只填域名，不带路径
# 微信支付商户平台
支付回调域名      www.bliot.cn          ← 路径由系统自动拼成 /platform/api/pay/notify/wxpay
```

> 域名解析**什么都不用做** —— `www.bliot.cn` 已经指向服务器了。
>
> 一个前提要记住：微信的「网页授权域名」是按域名配的。填了 `www.bliot.cn` 之后，
> **这个域名下的微信授权就归你这个服务号了**。官网以后若也要做微信登录，会打架。

想改回根路径或换成子域名，把 `BASE_PATH` 去掉、换回 `deploy/nginx.conf` 即可，代码两种都支持。

你的环境已经装好了 Node / Nginx / PM2，所以脚本**不会重装、不会覆盖**，只做体检再逐项问你。按这个顺序：

```bash
# ① 先只读体检，看看还缺什么（不改任何东西）
sudo bash deploy/setup-ubuntu2204.sh --check www.bliot.cn

# ② 确认报告没问题后，让它按你的选择补齐（每步都会先问）
#    证书那一步会检测到你已有 HTTPS，直接跳过不会重签
sudo bash deploy/setup-ubuntu2204.sh www.bliot.cn

# ③ 推代码前也先体检一次
cd /opt/blcloud && bash deploy/deploy.sh --check

# ④ 正式部署
bash deploy/deploy.sh --init

# ⑤ 配 Nginx：把 location /platform/ 那段加进官网现有 server 块
#    或直接套用 deploy/nginx-subpath.conf（改里面的证书路径为你的）
sudo nginx -t && sudo systemctl reload nginx

# ⑥ 拿初始管理员密码
sudo cat /opt/blcloud/data/admin-init-password.txt
```

### 脚本不会碰的东西

| 你的现有环境 | 脚本行为 |
|---|---|
| 已装的 Node（若不是 22） | **不自动升级**，只提示并给你命令。同机有其他 Node 项目时升级会出事 |
| Nginx 已有站点 | 只新增 `blcloud.conf`，不碰 `/etc/nginx/conf.d/` 下其他文件 |
| ufw 现有规则 | **绝不 reset**，只补缺失的 22/80/443；ufw 未启用时会先警告断连风险再问你 |
| 已有 `/opt/blcloud/data/` | 数据库只备份不删除；升级场景会明确提示「这是升级不是首次安装」 |
| 被覆盖的配置文件 | 覆盖前自动带时间戳备份成 `xxx.bak-20261031-120000` |
| 3000 端口被别的程序占 | 只提示，让你自己改 `ecosystem.config.cjs` 里的 PORT |

### 三种模式

```bash
--check     # 只读体检，输出报告后退出，零改动
（默认）     # 体检 → 每一项都先问你 y/n → 才执行
ASSUME_YES=1 # 非交互，全部按推荐值执行（推荐值：装依赖=y，启用 ufw=n，申请证书=n）
```

> 没有交互终端（比如管道执行）时，所有询问默认**跳过**，不会自作主张改系统。

然后登录后台 `https://www.bliot.cn/platform/admin/`，按下面的对应关系填：

| 后台位置 | 填什么 |
|---|---|
| 接入配置 → 微信服务号 | AppID、AppSecret、Token、EncodingAESKey，启用 |
| 接入配置 → 微信支付 v3 | 商户号、AppID、API v3 密钥、证书序列号、商户私钥，**新商户号还要填微信支付公钥ID与公钥内容**，启用 |
| 接入配置 → 支付宝 | **保持关闭** |
| 站点设置 → 演示模式 | **强制关闭** |
| 站点设置 | 站点名称、Logo、备案号、联系方式 |

微信服务号后台要填：
- 服务器地址 URL：`https://www.bliot.cn/platform/api/wechat/server`
- 网页授权域名：`www.bliot.cn`（只填域名，不带路径）
- IP 白名单：服务器公网 IP

微信支付商户平台要填：
- 支付回调域名：`www.bliot.cn`（系统自动拼出 `/platform/api/pay/notify/wxpay`）
- 产品：**Native 支付**（系统走的就是扫码付）

> 后台「接入配置」页面显示的回调地址会自动带上 `/platform` 前缀，照着抄到微信后台即可，
> 不用自己手动拼。**回调地址填错 = 用户付了钱但收不到通知、不发授权**，这是最容易踩的坑。

调通后按「六、上线检查清单」逐项打勾，特别是**真实支付 1 分钱**那一条。

## 一、是不是必须上服务器？

**分三块看，不是全都要：**

| 能力 | 本机能否跑 | 原因 |
|---|---|---|
| 产品建档、官方上架、生成授权码、订单/用户/授权管理、统计查看 | ✅ 本机完全可用 | 纯内网 CRUD |
| 软件端激活授权、心跳、API 消费上报 | ❌ 必须公网 | 客户端要能访问到你的域名 |
| 微信扫码登录、微信/支付宝支付 | ❌ 必须公网 + HTTPS + 已备案域名 | 微信/支付宝服务器要回调你的接口，且国内服务器域名必须备案 |

**结论**：做产品管理和发授权码，本机就够；要让用户真正能扫码登录、付款、软件联网激活，必须部署到有公网 HTTPS 域名的服务器。

## 二、上线前要备齐的东西

### 1. 服务器
- 最低 2 核 4G / 40G 盘，Linux（Ubuntu 22.04 或 CentOS 7+）
- **不要**买 Windows Server 跑这套（SQLite + 原生模块在 Linux 上省心得多）
- 开放端口：80、443（**3000 不要对公网开放**，只让 Nginx 本机反代）

### 2. 域名 + 备案
- 一个域名，例如 `admin.yourcompany.com`
- **国内服务器必须备案**，没备案微信和支付都接不了（微信服务器调不通未备案域名）
- 解析到服务器公网 IP

### 3. HTTPS 证书
```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d admin.yourcompany.com
```
证书 90 天过期，certbot 会自动续期，确认一下定时任务在：
```bash
systemctl status certbot.timer
```

### 4. 微信服务号（扫码登录用）
- 必须是**认证服务号**（订阅号没有网页授权与二维码接口）
- 后台 → 开发 → 基本配置：
  - `AppID` / `AppSecret`
  - `服务器配置 Token` / `EncodingAESKey`
  - **URL 填**：`https://admin.yourcompany.com/api/wechat/server`（GET 校验 + POST 收消息，同一个地址）
  - IP 白名单加服务器公网 IP
- 后台 → 设置 → 公众号设置 → 功能设置：
  - **网页授权域名**填：`admin.yourcompany.com`（不带 https://，不带路径）

> **微信内免扫码登录**：上面「网页授权域名」配好后，微信里打开用户中心（`/platform/user/`）
> 会自动静默登录，不再要求扫码。后台「接入配置 → 微信服务号」可选授权范围：
> `snsapi_base`（默认，完全静默，拿不到昵称）/ `snsapi_userinfo`（首次弹一次「允许」，可拿昵称头像）。
> 已关注公众号的用户两种模式都能补到微信昵称；未关注用户显示「用户XXXX」，可在账户中心自行改名。
> 常见坑：redirect_uri 参数错误 = 网页授权域名没配或填了带 `https://` / 路径 / 端口的值。

### 5. 微信支付（可选）

商户平台（pay.weixin.qq.com）上要做的四件事：

**① 拿商户号**
账户中心 → 商户信息 → 记下 `微信支付商户号`（`mchid`，纯数字）。

**② 设置 API v3 密钥**
账户中心 → API安全 → **设置APIv3密钥** → 自己设一个 32 位字符串（记牢，系统里要用）。

**③ 申请 API 证书（关键，最容易卡住）**
账户中心 → API安全 → **申请API证书** → 按提示用「微信支付商户平台证书工具」生成，最终得到三个东西：

| 文件/值 | 用在哪 |
|---|---|
| `apiclient_key.pem` | 粘贴到后台「商户私钥」文本框（**全文，包含 BEGIN/END 两行**） |
| `apiclient_cert.pem` | 只用来在商户平台看**证书序列号**，不用上传 |
| 证书序列号（一串十六进制） | 填后台「商户 API 证书序列号」 |

证书序列号怎么看：商户平台 → API安全 → API证书 → 查看证书序列号；或用命令：
```bash
openssl x509 -in apiclient_cert.pem -noout -serial
# 输出 serial=XXXXXXXX，去掉 serial= 前缀填进去
```

**④ 配回调域名**
产品中心 → 开发配置 → 支付配置 → 添加 `admin.yourcompany.com`。
> 系统里的「回调地址」字段可留空，会自动用当前站点域名拼出 `https://域名/api/pay/notify/wxpay`。只有当你想让回调走另一个域名时才填。

后台「接入配置 → 微信支付 v3」最终要填 5 项：`商户号` `应用AppID`（一般等于服务号 AppID）`API v3 密钥` `证书序列号` `商户私钥`。

**⑤ 微信支付公钥（新商户号必填，最容易漏）**

2024 年起新开的商户号**已经不再提供平台证书下载**。如果回调日志出现：

```
无可用的平台证书，请在商户平台-API安全申请使用微信支付公钥｜错误码 RESOURCE_NOT_EXISTS
```

说明你的商户号是公钥模式，必须再补两项（下单能成功，但回调永远验不了签）：

- 商户平台 → 账户中心 → API安全 → **申请「微信支付公钥」**
- 把**公钥ID**（形如 `PUB_KEY_ID_xxx`）填到后台「微信支付公钥ID」
- 把**公钥内容**（`-----BEGIN PUBLIC KEY-----` 整段）填到后台「微信支付公钥内容」

填了公钥后，回调**直接在本地验签，不再联网拉证书**，链路最短也最稳；后台「验签模式」会显示「微信支付公钥（本地验签）」。

> 公钥和平台证书都是公开信息（只用于验签，不是密钥），所以后台明文保存、可随时清空重填。
> 老商户号可以不填这两项，系统仍会用 API v3 密钥自动从 `/v3/certificates` 拉取平台证书，12 小时刷新一次。

### 6. 支付宝（可选）

**没开通就别启用。** 系统在渠道未开通时会直接报错「支付宝尚未开通」，不会静默降级成模拟支付；前端也不会显示支付宝按钮。
- 开放平台创建**网页/移动应用**，签约「电脑网站支付」
- 用支付宝密钥工具生成应用公私钥，把**应用公钥**上传到平台拿**支付宝公钥**
- 应用网关与回调地址：`https://admin.yourcompany.com/api/pay/alipay/notify`

### 7. 短信（手机号绑定用，可选）
- 阿里云/腾讯云短信服务：拿 `AccessKey` / `Secret` / `签名` / `模板Code`
- 没配也能跑，只是验证码接口只写日志不发短信

## 三、部署步骤

### 方式 A：rsync 推送（推荐，从开发机推）

`deploy/deploy.sh` 已写好，把 `--init` 用于首次，之后不带参数就是更新。

```bash
# 首次
bash deploy/deploy.sh --init

# 以后更新
bash deploy/deploy.sh
```

脚本做的事：同步代码（**排除 node_modules 和 data**）→ 服务器本地编译依赖 → 备份数据库 → 重启 → 健康检查。

### 方式 B：git + 手动

```bash
# 服务器上
git clone <你的仓库> /opt/blcloud
cd /opt/blcloud
npm ci --omit=dev

mkdir -p /var/log/blcloud
useradd -r -s /bin/bash -d /opt/blcloud blcloud
chown -R blcloud:blcloud /opt/blcloud /var/log/blcloud

# 二选一：PM2 或 systemd
npm i -g pm2
pm2 start deploy/ecosystem.config.cjs
pm2 save && pm2 startup      # 开机自启

# 或者 systemd
cp deploy/blcloud.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now blcloud
```

### 方式 C：Windows 服务器

不推荐，但要用就：
1. 装 Node 22 LTS（**必须和开发机大版本一致**，否则原生模块要重编）
2. `npm ci --omit=dev`（需要 VS Build Tools 编译 better-sqlite3，或用预编译包）
3. 进程守护用 `node-windows` 或「任务计划程序」
4. 反代用 Nginx for Windows，或直接 Caddy（自带 HTTPS）

## 四、Nginx 配置

```bash
cp deploy/nginx.conf /etc/nginx/conf.d/blcloud.conf
# 改里面的 your-domain.com 为你的真实域名
nginx -t && systemctl reload nginx
```

配置已包含：HTTPS 强制跳转、`/uploads/` 静态直出、**拦截 .html/.svg 防存储型 XSS**、安全响应头、200MB 包体上限。

## 五、部署后必须在后台配置的东西

登录管理后台 → **站点设置 / 接入配置**，逐项填：

| 位置 | 配置项 | 说明 |
|---|---|---|
| 站点设置 | 站点名称、Logo、备案号 | 前端展示用 |
| 站点设置 | **演示模式** | 上线后设为「强制关闭」，否则模拟扫码/模拟支付开着等于后门 |
| 接入配置 | 微信 AppID / AppSecret / Token / AESKey | 填了之后模拟扫码自动停用 |
| 接入配置 | 微信支付商户号 / API v3 密钥 / 证书 | |
| 接入配置 | 支付宝 AppID / 应用私钥 / 支付宝公钥 | |
| 接入配置 | 短信 AccessKey / Secret / 签名 / 模板 | |
| 开放接口 | 各软件应用 AppKey / AppSecret | 发给软件端用；**每个应用必须绑定一个已上架的软件商品** |
| 产品运营 → 套餐档位 | 按应用配置专属档位 | 选中应用 → 「从模板复制到该产品」→ 按实际价格/周期/权益改。通用模板（`app_id` 为空）只作底稿，不直接售卖；未配套餐的产品用户端不展示 |

> 升级到「多产品套餐」版本时，启动会自动把旧 `plans` 表（code 全局唯一）重建成按 `(app_id, code)` 唯一的表，并补 `licenses.app_id` / `orders.app_id` / `users.profile_custom` 三列。迁移在事务里完成且可重复启动，但**重启前务必先备份 `data/app.db`**（连同 `data/.appsecret`）。迁移后原有五档会变成「通用模板」，需要为每个应用复制一份专属档位，老用户已售授权不受影响。

**环境变量**（写进 PM2 config 或 systemd unit）：

```bash
NODE_ENV=production    # 必须！不开则演示接口默认开放
PORT=3000
TRUST_PROXY=1          # 走 Nginx 反代时开，否则登录锁定拿到的全是 127.0.0.1
```

## 七、备份、恢复与清理

账套 = `app.db` + `data/.appsecret`（+ 可选 `data/uploads`）。三样必须一起走：
`.appsecret` 是配置密文的 AES 主密钥，**只恢复数据库不恢复它，微信商户私钥、API v3 密钥全部解不开**。

### 1. 后台一键（日常用这个）

**系统 → 备份与恢复**：

- 「立即备份」→ 生成 `data/backups/blcloud-YYYYMMDD-HHmmss.zip`，可勾选是否含上传文件
- 列表里直接「下载」到本机 —— **必须存一份到服务器之外**，只放服务器上等于没备份
- 「从备份恢复」：上传 zip → 系统先校验（SQLite 头、`integrity_check`、必备表、sha256）→ 预览摘要 →
  输入 `RESTORE` 才真正写入
- 恢复是**单事务原地覆盖**，不用重启进程，失败整体回滚；执行前还会自动再备份一份当前数据（`pre-restore-*`）

服务启动时每天自动留一份（同日只留一份），保留最近 30 份。想关掉就删 `server/index.js` 里的 `snapshot()` 定时器。

### 2. cron 命令行（服务器层面兜底）

```bash
# 每天 03:10，与后台同一套实现、同一目录、同一种 zip 格式
10 3 * * * cd /opt/blcloud && BACKUP_KEEP=30 node deploy/backup.js >> /var/log/blcloud/backup.log 2>&1
```

- `BACKUP_UPLOADS=0` 不含上传文件，包更小
- `BACKUP_KEEP=N` 保留份数（默认 30）
- 生成的包在后台列表里同样能看到、能一键恢复，不用记两套格式

### 3. 整机还原（换服务器 / 被入侵后重建）

后台恢复只覆盖数据行，不动 `.appsecret` 和上传文件。要连密钥一起回到备份那一刻，用命令行走文件级还原：

```bash
pm2 stop blcloud-admin                       # 必须先停，运行中的进程还持有旧库句柄
node tools/restore-backup.js data/backups/blcloud-20261104-1200.zip --yes
pm2 start blcloud-admin && pm2 logs blcloud-admin
```

脚本会：校验包 → 把现有库备份成 `pre-cli-restore-*.db` → 删掉 `app.db-wal/-shm` 再替换（不删会被旧 WAL 覆盖回去）
→ 还原 `.appsecret`（旧的另存 `.bak-<时间戳>`）→ 还原 `uploads/`。

### 4. 清空演示 / 测试数据

**系统 → 备份与恢复 → 清理演示数据**，按分组勾选（订单/授权/佣金/设备/用户/日志/统计/商品/软件应用），
输入「清除」执行。命令行等价：

```bash
node tools/clear-demo.js                                   # 只预览，打印每张表将删多少行
node tools/clear-demo.js --yes                             # 默认分组（保留管理员/站点配置/套餐模板/商品）
node tools/clear-demo.js --groups=transactions,users,catalog,apps --yes
```

规则：

- **只删数据行，不删表、不删管理员、不删站点与接入配置** —— 清理完后台仍能登录
- 勾「用户账号」会自动连带清空该用户衍生的订单、授权、佣金、设备，不留孤儿数据
- 执行前自动备份 `pre-purge-*.zip`，删错能退回
- 删完 `VACUUM` 回收磁盘；同时写 `seed_products_done` / `seed_stats_done` 标记，
  **重启后不会被 `seed()` 重新种回去**（否则会出现「清完又回来了」）

### 5. 被攻击后的处置顺序

1. **先断源**：改 nginx 只放行自己的 IP，或 `pm2 stop`；别让攻击者继续写
2. **留证**：整目录打包 `tar -czf /tmp/incident-$(date +%F).tgz /opt/blcloud/data`（含日志与库，供事后分析）
3. **查入口**：`grep -E 'POST /api/(wechat/simulate|pay/simulate)' /var/log/nginx/access.log`；
   确认 `NODE_ENV=production`（否则演示后门是开的）、管理员密码是否被改、`admins` 表是否多出账号
4. **重置**：改管理员密码、重发 `data/.appsecret` 会作废所有加密配置（除非确认未泄露，一般不换）、
   吊销全部 `client_sessions` 与授权
5. **恢复**：按上面第 3 步还原到被入侵前的备份；没有可用备份时，用第 4 步的清空功能回到干净状态再重配
6. **补洞**：核对 `docs/部署上线指南.md` 与工作记忆里的「上线前必须封堵的口子」清单

## 八、常见坑

### 本机调试 vs 线上（重要）

填了微信 AppID/Secret 之后，**模拟扫码登录会被永久禁用**（这是安全设计，`dev_simulate` 也覆盖不了）。所以：

| 场景 | 微信配置 | 演示模式 | 结果 |
|---|---|---|---|
| 本机 localhost 调试 | **留空** | 开启 | 可用模拟扫码登录、模拟支付 |
| 线上服务器 | 填真实值 | 强制关闭 | 走真实微信扫码 + 微信支付 |

线上配好微信后本机仍能调试 —— 因为线上和本机是两套独立的 `data/app.db`。

### 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 服务起不来，`was compiled against a different Node.js version` | 开发机的 `node_modules` 被拷到服务器 | 服务器上重新 `npm ci` |
| 填了微信配置后本机没法登录用户端 | 模拟扫码被安全策略禁用 | 本机那套库别填微信配置，见上表 |
| 支付弹窗显示「未开通任何支付方式」 | 微信支付没启用，且 `pay_simulate` 未开 | 线上启用微信支付；本机演示则后台开「模拟支付」开关 |
| 微信支付下单报「签名错误」 | 证书序列号填错，或私钥粘漏了首尾行 | 用 `openssl x509 -noout -serial` 重新确认；私钥要含 `-----BEGIN PRIVATE KEY-----` 整段 |
| 下单成功、扫码付款成功，但订单一直是待支付 | 回调验签失败（微信的重试用完了就不会再通知） | 后台「支付诊断」看最近一次 notify 错误；报 `RESOURCE_NOT_EXISTS`/无可用的平台证书时，去商户平台申请「微信支付公钥」填到后台；已付款的订单在订单管理点「向微信查单」补齐 |
| 端口 3000 被占 | 机器上另有服务 | 换 `PORT`，或 `lsof -i:3000` 查占用 |
| 支付回调收不到 | 域名未备案 / 不是 HTTPS / Nginx 没转发 | 检查备案与证书；看 `/var/log/nginx/blcloud.access.log` |
| 扫码登录一直转圈 | 网页授权域名没配，或 IP 不在白名单 | 公众号后台检查这两项 |
| 登录失败计数对所有人一起生效 | 没开 `TRUST_PROXY=1`，IP 全是 127.0.0.1 | 加环境变量重启（锁定按用户名算，实际影响有限但日志会失真） |
| 更新后页面还是旧的 | 浏览器缓存了 JS | Nginx 已对 html 设 `no-store`，强刷一次 |
| **git pull + 重启后整站 502** | 后端进程启动即崩，PM2 反复重启，3000 没监听 | 先看 `pm2 logs blcloud-admin --lines 100 --nostream`，多半是 SQLite 迁移报错（如 `no such column: app_id`）；`git pull` 到最新版再重启。**升级前务必备份 `data/app.db` 与 `data/.appsecret`** |
| 重启后加密配置全变空 | `.appsecret` 丢了 | 从备份恢复该文件 |

#### 子路径部署专属的三个坑（`BASE_PATH`，2026-10-31 实测）

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面能开，`.css` / `.js` 全部 404 | 官网 server 块里有 `location ~* \.(css\|js\|png\|woff2?)$` 之类的**正则** location，**优先级高于普通前缀 location**，把子路径下的静态资源截胡到主站目录去找 | 把 `location /platform/` 改成 `location ^~ /platform/`（`^~` = 匹配到即停，不再走正则），然后 `nginx -t && systemctl reload nginx` |
| `curl 127.0.0.1:3000/api/health` 是 200、`/platform/api/health` 是 404 | `BASE_PATH` **没进进程** | 见下条 |
| 改了 `ecosystem.config.cjs` 的 `BASE_PATH` 并 `pm2 restart --update-env` 后仍不生效 | **PM2 的 `--update-env` 不会读入配置里新增的环境变量**（实测于 PM2 7.0.4） | 用彻底重启：`pm2 delete blcloud-admin && pm2 start deploy/ecosystem.config.cjs && pm2 save`；验证：`pm2 env <id> \| grep BASE_PATH` |
| `pm2 env blcloud-admin` 报 `Modules with id blcloud-admin not found` | PM2 的 `env` 子命令只接受 id 不接受进程名 | 用 `pm2 list` 查 id，再 `pm2 env <id>` |
| 访问 `/platform/` 显示系统 404 页 | 子路径根本身没有首页，这是**正常行为** | 访问 `/platform/admin/`（结尾斜杠要有） |

**验证子路径是否真正生效的一条命令**：

```bash
curl -s -o /dev/null -w '子路径 %{http_code}\n' http://127.0.0.1:3000/platform/api/health   # 期望 200
curl -s -o /dev/null -w '根路径 %{http_code}\n' http://127.0.0.1:3000/api/health            # 期望 404（说明整体迁到 /platform/ 下了）
```

#### 升级后 502 的定位顺序

502 是 **Nginx 反代不到后端**，不是前端问题，先确认进程再猜业务逻辑：

```bash
pm2 list                                          # 状态是不是反复 restart / errored
pm2 logs blcloud-admin --lines 100 --nostream      # 第一行报错基本就是根因
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/platform/api/health
tail -50 /var/log/nginx/blcloud.error.log
```

**2026-11-03 实测过的一次**：`schema.sql` 在「建表阶段」就执行 `CREATE INDEX ... ON licenses(app_id)`，
而这个列是由 `server/db/index.js` 的 `ensureColumn()` 在后面才补的；**全新库没问题，旧库升级必崩**，
报 `SqliteError: no such column: app_id` → 进程起不来 → 502。修复方式是把 schema.sql 里的索引语句挑出来，
等 `ensureColumn()` 全部跑完再统一执行（`server/db/index.js` 顶部有注释）。回归测试
`tools/test-plans-migration.js` 用**真实上一版 schema** 造旧库并做了反向验证，以后新增列时记得重跑它。

注意：这类崩溃发生在 `db.exec(schema.sql)` 阶段，`plans` 重建迁移根本没执行，且前面都是
`CREATE TABLE IF NOT EXISTS`，所以**数据库没有被改坏**，直接拉到修复版重启即可，不需要回滚数据。
