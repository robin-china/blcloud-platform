# 账户中心改造说明（2026-11-13）

范围：用户端「账户中心」UI、对外用户身份字段、头像、手机绑定、积分充值。
依据：用户 2026-11-13 验收反馈。

---

## 1. 逐条落地

| 反馈 | 做法 |
|---|---|
| UI 占地方太大，尤其头像设置 | 账户中心改为**单列紧凑布局**（`.acct`），去掉整排卡通头像网格与「高级：图片链接」折叠区；资料、积分、明细收进两张卡；移动端 560px 断点重新排版 |

| 手机验证别做成一整个窗口 | 主页面只留「手机号（脱敏）+ 绑定/更换按钮」，点击弹 `<teleport to="body">` 模态框完成验证；带滚动锁与 Esc |

| 移动端 / PC 适配 | `ui.css` 加 `.acct-*` 布局，560px 断点：头像缩小、编辑区改纵排、档位 3 列改 2 列、积分明细表可横向滚动 |
| 积分可充值，¥1 = 100 积分 | 账户中心「充值」→ 档位/自定义金额 → 走现有订单与支付链路 → 回调发货到 `users.points` |

## 2. 资金口径（积分充值）

- **汇率**：¥1 = 100 积分，与既有「100 积分抵 ¥1」下单抵扣汇率对称。
- **服务端定价**：只收 **1~1000 的整数元**，`points = yuan * 100`。前端传 `points` 一概不认；小数金额**明确报错**，不静默截断（否则 ¥1.5 被截成 ¥1 会少收钱）。
- **禁止积分抵扣充值订单**：充值单 `discount` 恒为 0，忽略 `use_points`。否则「用积分买积分」会循环放大。
- **发货**：`orders.kind = 'points_recharge'`，支付成功后由 `deliverOrder()` 走 `lib/points.js` 的单一入口加到 `users.points` 并写 `points_logs`，`deliver_result` 记录 `type:'points'`（后台与用户订单列表都已覆盖展示）。
- **不叠加消费返积分**：普通订单支付后会返 `floor(pay_amount)` 积分，充值订单跳过这一步（否则 ¥1 实际到账 101 积分，流水也对不上）。退款侧同样跳过「收回消费返积分」。
- **退款反向回收**：按 `deliver_result` 收回发放的积分；用户已花掉的部分最多扣到 0，流水记实际扣减量。
- **代理商佣金**：仍按实收计，充值订单与其它订单一致。
- **支付渠道**：沿用 `/api/portal/site` 的 `pay_channels` 动态渲染；渠道未开通时 `createPayment` 直接抛错，**不会降级成模拟支付**。

前端流程：账户中心「充值」→ 选档位 → `POST /api/portal/orders` → 通用 `pay-dialog` 组件下单支付、展示二维码 → 「我已完成支付」查单 → 到账刷新余额与明细。「我的订单 → 继续支付」对充值单复用同一弹层。

## 3. 对外契约变更（软件端必须知悉）

**所有返回 `user` 的开放接口不再下发 `openid`**，改为 `publicId`（9 位数字字符串）。
涉及：激活、扫码登录、手机号登录、`/user/profile`、`verify`、`heartbeat`、`refresh` 等。
其余字段不变；软件端不要用 openid 做本地用户标识或缓存。
详见《软件端接入API.md》§3 醒目提示与 §5 行为要点。

顺带订正了文档 §3 里一处旧示例：示例中的 `tb_username` 属于内部凭据，实际接口从不返回，已从示例删除。

## 4. 头像上传安全

与模板市场缩略图**共用同一套**校验与内容寻址落盘（`lib/market.js` 的 `sniffImage` / `thumbExtOf` / `storeThumbnail`）：

- 按文件头魔数识别 PNG / JPEG / GIF / WebP，扩展名必须与内容一致，拒 SVG / HTML 改名伪装；
- ≤2MB；可声明 `X-File-Sha256` 比对，不符拒收且不覆盖；
- 文件名 `mkt-<内容 sha256 前 20 位>.<ext>`，**上传者文件名不参与落盘路径**；
- 落 `data/uploads/` 由 Nginx 直出（缩略图/头像都是公开图片），Nginx 的 `.html/.svg` 403 拦截必须保留；
- 与 `.blls` 模板文件仍是两条路：模板文件只在私有 `data/market/`，永不直出。

**已知取舍**：上传头像在库里/接口里是站内相对路径（不是 data URI），因为 2MB 图片塞进
`user` 响应会把每次登录/同步都拖垮。软件端需拼服务端基址后渲染，离线时用昵称首字占位兜底；
网页端在子路径部署下可直接使用该路径。已在《软件端接入API.md》§5 写明三种 avatar 形态。

## 5. 数据库与部署

- 新增 `users.public_id` 列（`ensureColumn` 兼容旧库）+ 部分唯一索引
  `idx_users_public_id ... WHERE public_id<>''`（空值不参与约束）。
- 老账号**懒生成**：首次登录或后台列表/详情查询时补上，不追溯改库。

- 部署：`cd /opt/blcloud && git pull && pm2 restart blcloud-admin`
