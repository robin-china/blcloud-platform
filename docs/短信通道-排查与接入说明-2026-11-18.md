# 短信通道 · 排查与接入说明

日期：2026-11-18
现象：后台/用户端点「发送验证码」提示成功，但手机收不到短信；开放接口也拿不到可用验证码。
范围：用户端手机绑定 `/api/portal/phone/code`、软件端手机号登录 `/api/open/v1/auth/sms/send`。

---

## 1. 结论：不是服务商故障，是发送链路根本没接

排查源码得到的事实（修复前）：

| 位置 | 实际行为 |
|---|---|
| 后台「接入配置 → 短信」 | 能保存 `enabled / vendor / access_key / secret / sign_name / template_code`，**但没有任何代码读取它来发短信** |
| `/api/portal/phone/code` | 生成 6 位码 → 写 `sms_codes` → 回 `{ok:true}`（开发模式额外回 `devCode`）。**无服务商调用** |
| `/api/open/v1/auth/sms/send` | 同上，且**无条件**回 `dev_code: code` —— 生产环境等于把验证码直接交给调用方 |
| `server/services/` | 只有 `alipay.js` / `wxpay.js` / `wechat.js` / `tb.js` 等，**没有任何短信模块** |
| 文档 | 《部署上线指南》§7 写着「没配也能跑，只是验证码接口只写日志不发短信」，描述的是当时状态 |

所以无论选阿里云还是腾讯云、填不填 AccessKey，接口都返回「成功」——**假成功**，
用户看到「验证码已发送」却永远收不到。同时开放接口还留着一个生产后门。

### 顺带发现的三个隐患

1. 发码端点**没有任何频控**，登录态账号可无限调用（短信轰炸 / 烧钱 / 被停号）；
2. 验证码**明文入库**、表里没有 IP / 发送时间 / 尝试次数，事后无法对账；
3. 发送失败也回 `{ok:true}`，运营完全无法从界面判断到底发没发。

---

## 2. 本轮修复

新增 `server/services/sms.js`（零新依赖，Node 内置 `fetch` + `crypto`）：

- **阿里云**：Dysmsapi `2017-05-25` RPC V1 签名（`HMAC-SHA1` + `percentEncode` 规范），GET 请求；
- **腾讯云**：SMS `2021-01-11` + `TC3-HMAC-SHA256`，POST / JSON，`+86` 号码、`SmsSdkAppId`、单变量 `TemplateParamSet`；
- 两家请求头**显式写死**（Node 内置 fetch 会自作主张补 `accept-language` / `sec-fetch-mode`），8 秒超时；
- 服务商原始错误码、RequestId、回执号全部留痕，但响应**不回传任何密钥**。

两个发码端点统一改造：

- **先真发成功，再写 `sms_codes`** —— 发送失败绝不留一条能用于登录的码；
- 未启用 / 配置不全 / 生产仍是开发模式 → 明确 503，**绝不静默降级、绝不假成功**（与支付渠道同口径）；
- `devCode` / `dev_code` **只在非生产 + 开发模式**回显；生产一律不下发；
- 频控：同号码 60 秒 1 条 / 每日 10 条，同 IP 每小时 30 条；
- 新增 `sms_send_logs` 台账（成功/失败都记，留存 30 天），兼作频控依据。

后台「接入配置 → 短信」新增：

- `SmsSdkAppId` 字段（腾讯云必填）；
- **发送自检**（不发短信，直接列出缺哪个字段、为什么发不出去）；
- **发送测试短信**（真发一条、会计费，前端二次确认，失败直接显示服务商错误码）；
- 最近发送台账表格。

## 3. 怎么配（按顺序）

1. `cd /opt/blcloud && git pull && pm2 restart blcloud-admin`（重启自动建 `sms_send_logs` 表与索引，无需手工 SQL）；
2. 后台「接入配置 → 短信」打开**启用**，选择服务商；
3. 填字段后点**保存**，再点**发送自检**，确认状态是「可发送」、缺失字段为「无」；
4. 填自己的手机号点**发送测试短信**，确认手机真的收到，控制台/台账显示 `OK`；
5. 生产环境确认没有停留在「开发模式」。

| 服务商 | 字段 | 从哪拿 |
|---|---|---|
| 阿里云 | AccessKey / Secret | RAM 访问控制，需具备 `dysms:SendSms` 权限 |
| 阿里云 | 签名 / 模板 Code | 短信服务控制台，必须**审核通过** |
| 腾讯云 | SecretId / SecretKey | 云 API 密钥 |
| 腾讯云 | 签名 / 模板 ID | 短信控制台正文模板管理 |
| 腾讯云 | **SmsSdkAppId** | 短信控制台「应用管理」，形如 `1400006666`；**不是**云 API AppId |

### 腾讯云 SecretId / SecretKey 到底在哪

**不是短信控制台里的东西**，是账号级的云 API 密钥：

- 直达：<https://console.cloud.tencent.com/cam/capi>
- 菜单：控制台右上角**头像 → 访问管理 → 访问密钥 → API 密钥管理**
- 页面列出 `SecretId`，点「**显示**」查看 `SecretKey`（需短信/邮箱验证身份）
- 用**子账号**（推荐）：主账号进「用户 → 用户列表 → 点子账号 → API 密钥」新建密钥，
  并在「权限」里关联预设策略 **`QcloudSMSFullAccess`**（或自定义含 `sms:SendSms` 的策略）

填法：后台「AccessKey / SecretId」← `SecretId`；「Secret」← `SecretKey`。
Secret 加密入库、列表显示掩码，**留空表示不修改**（要换密钥就填新值）。

四个容易拿错的值：

| 值 | 位置 | 用途 |
|---|---|---|
| `SecretId` / `SecretKey` | 访问管理 CAM → API 密钥管理 | **本配置要填的** |
| `SmsSdkAppId`（如 1400006666） | 短信控制台 → 应用管理 → 应用列表 | 填「SmsSdkAppId」字段 |
| 账号 `APPID`（如 130xxxxxxx） | 账号信息 | **不用**，别混 |
| 签名 / 模板 ID | 短信控制台 → 签名管理 / 正文模板 | 填「签名」「模板」字段 |

两个高频报错：

- `UnauthorizedOperation.SmsSdkAppIdVerifyFail` —— SdkAppId 与云 API 密钥**不属于同一主账号**
  （常见于用了别的主账号下的子账号密钥）；换同账号密钥即可。
- `AuthFailure.UnauthorizedOperation` —— 子账号没授 `QcloudSMSFullAccess` / `sms:SendSms`。
- 复制粘贴注意别带首尾空格或换行，否则会报 `AuthFailure.SignatureFailure`。

**模板必须是单变量验证码模板**，变量名固定 `code`。阿里云 `TemplateParam` 会发
`{"code":"123456"}`；腾讯云按变量顺序只传一个值 `["123456"]`。模板里若还有其它变量，
会收到 `FailedOperation.TemplateParamSetNotMatchApprovedTemplate` / `isv.TEMPLATE_MISSING_PARAMETERS`。

## 4. 错误码对照（排障按顺序看）

| HTTP | code | 含义 | 处理 |
|---|---|---|---|
| 503 | `SMS_DISABLED` | 「启用」开关没打开 | 后台打开开关 |
| 503 | `SMS_CONFIG_MISSING` | 缺字段（自检会列出具体项） | 补齐；腾讯云最常见是漏 `SmsSdkAppId` |
| 503 | `SMS_SIMULATE_FORBIDDEN` | 生产环境仍是开发模式 | 切成阿里云/腾讯云并填凭据 |
| 429 | `SMS_RATE_LIMITED` | 60 秒 / 每日 / 同 IP 限流 | 等倒计时；别让客户端无限重试 |
| 502 | `SMS_VENDOR_ERROR` | 服务商拒绝 | **看后台台账里的原始错误码**：`InvalidAccessKeyId` 密钥错、`SignatureDoesNotMatch` 签名/时间错、`isv.BUSINESS_LIMIT_CONTROL` 服务商侧流控、`isv.INVALID_PARAMETERS` 模板变量不匹配、欠费类错误去控制台充值 |
| 502 | `SMS_NETWORK_ERROR` | 连不上服务商 / 超时 | 查服务器出网与 DNS；8 秒超时 |

排障顺序：**自检 → 测试发送 → 台账原始错误码 → 服务商控制台**。
发送台账只存手机号、渠道、结果码与描述，不存密钥、不存验证码。

## 5. 契约变更（软件端必看）

- `/auth/sms/send` 响应新增 `mode`（诊断用，客户端不必解析）；
- **`dev_code` 生产环境不再下发**。此前无条件返回，正式包若依赖它做联调会失效——
  请改用本地/测试环境；
- 发送失败不再回 `{ok:true}`，会带上述 `code`，客户端要按提示等待或报错，不要无限重试。

《软件端接入API.md》§5.8 已同步。

## 6. 验证与已知取舍

- `tools/test-sms.js` **46 项**：两家签名与独立重算逐字节比对、参数/请求头结构、
  服务商错误与网络异常透传、配置护栏、生产不外泄验证码、发送失败不入库、频控三档、
  后台自检/测试端点、配置页 Vue 模板真编译；
- 全量回归分批通过（每批 ≤8 个脚本，避免触发环境批量删除保护）。

**已知取舍（未做，别误以为已完成）：**

1. **签名实现按官方文档自研，未在真机用真实凭据验证过**。本地测试用拦截 HTTP 的方式
   验证签名串与参数结构，上线请务必按 §3 第 4 步真发一条；若报 `SignatureDoesNotMatch`，
   先查服务器时间是否偏差过大（两家签名都含时间戳）。
2. 验证码仍是**明文入库**（`sms_codes`）——本次为兼容现有校验逻辑未改；码存 HMAC 属于
   后台管理员第二因素 S2 的改造范围。
3. **这不是后台管理员的短信第二因素**。管理员侧还需要 `admins.phone` 加密预绑定、
   服务端按 username 查号发码（请求体不能有 phone）、一次性 challenge，与 TOTP 二选一；
   见《后台登录安全改造方案-2026-11-14.md》§9、§10。
4. 模板变量名固定 `code`，暂不支持多变量模板 / 自定义变量名。
5. 短信发送台账按 30 天滚动清理；清理会放宽历史频控判定，但频控窗口最长只有 24 小时，无影响。
