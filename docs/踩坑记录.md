# 踩坑记录

> 每条都是线上/本地真实踩过的，不是理论风险。改代码前先扫一眼相关章节。
> 新坑按「日期 + 现象 + 根因 + 修法」追加到对应章节末尾。

## 前端（Vue 无打包静态页）

### 1. in-DOM 模板禁止自闭合自定义组件标签
`<page-xxx />` 会把后续所有兄弟节点吞进组件里，页面直接缺一大块。必须显式写 `<page-xxx></page-xxx>`。

### 2. 页面脚本必须用 IIFE 包裹
禁止顶层 `const { ref } = Vue`——多个页面脚本共用全局词法作用域，重复声明会让**后续整个脚本失效**（不是只坏当前页）。

### 3. Vue 模板里禁止引用全局变量（2026-10-31 支付二维码崩过）
Vue 3 浏览器编译的模板只从 setup/data/props/`app.config.globalProperties` 找标识符。即使 `window.U` 存在，模板里 `U.basePath` 也是 undefined。需要就在 setup 里 `return` 出来；两端 App 已注册 `app.config.globalProperties.U = window.U` 兜底。注意：脚本里拼 HTML 字符串给 `v-html` 不受此限。

### 4. 原生 confirm 在内嵌浏览器被静默禁用（2026-11-04）
`confirm()` 返回 false 且无报错 → 删除操作「点了没反应」。统一用 `U.confirm()`（自绘确认框），删除类操作必须 try/catch + `U.failMsg()` 把错误显出来。

### 5. 模板 `:value` 里禁止写 `join('\n')`
模板字面量把 `\n` 求值成真换行，Vue 编译直接 SyntaxError。换行在 setup 里拼好（computed）再给模板。授权类页面踩过。

### 6. `.field label { display:block }` 压掉开关的 inline-flex（2026-11-05）
`ui.css` 里 `.field label` 优先级 (0,1,1) > `.switch` 的 (0,1,0)。凡在 `.field` 里的 `<label class="switch">` 被强制 block，`<span class="track">` 退化成 inline——宽高/背景全失效，轨道消失，只剩白色圆钮叠在文字上。修法：声明写成 `.switch, label.switch`（同优先级靠后者胜），`.track` 加 `display:inline-block; flex:none` 兜底。`test-ui-layout.js` 有断言守护。

### 7. 共用图标走 `U.icons` / `U.svgIcon()`
不要在各文件重复定义 ICONS。

## 后端（Fastify + better-sqlite3）

### 8. 子路径部署下所有 URL 拼接必须带斜杠意识
- `basePath()` 返回 `/platform` **无尾斜杠**，手写 `basePath() + 'user/'` 会拼出 `/platformuser/`（推广链接线上 404 过）。拼接用 `publicUrl(req, pathname)`，它自动补前导斜杠。
- `req.url.startsWith('/api/...')` 判定必须带 `basePath()`，否则子路径部署失效（微信支付回调栽过）。

### 9. 无斜杠目录 URL 会 404 掉整页资源（2026-11-05）
新版 @fastify/static 对 `/platform/admin`（无尾斜杠）**直接 200 返回 HTML，不再重定向**。页面里相对路径 `../assets/ui.css`、`js/app.js` 按无斜杠基准解析 → 全 404 → 样式丢失、脚本不执行、开关「不可操作」。修法：`server/index.js` 加 onRequest 钩子，public 下有 index.html 的目录无斜杠一律 301 补斜杠（保留查询参数）。`test-subpath.js` 有断言守护。

### 10. Fastify 5 的 redirect 签名是 `redirect(url, code)`
不是老版的 `(code, url)`。写反了会报 `Called reply with an invalid status code`。

### 11. Node 内置 fetch 会自动补默认头
对接第三方 API（微信支付 v3 实测）时，凡对方可能校验的头（accept-language、sec-fetch-mode 等）都**显式写死**，别依赖默认值。

### 11b. 微信公众号 API 裸 fetch → 空响应「Unexpected end of JSON input」（2026-11-08 线上踩过）
条目 11 的第二次现身：网页授权 `oauthAccessToken()` 等对 `api.weixin.qq.com` 全是裸 `fetch(url)`，
线上真实环境一直报「网页授权失败：Unexpected end of JSON input」——内置 fetch 补的
`accept-language: *` 等头让微信直接回空 body，`res.json()` 炸掉。**本地测试环境复现不了**（同一代码测试桩里是好的），只有线上真实微信接口才暴露。
修复：`server/services/wechat.js` 统一走 `wxFetch()`——显式写死 `Accept/Accept-Language/User-Agent`，
并用 `text()` + 手动 parse，空/非 JSON 响应报出 HTTP 状态码和原文片段。
教训：**所有对外 HTTP 调用必须过统一的带请求头封装**，`res.json()` 换成 text+parse 才能拿到可排障的报错。

### 12. multipart 测试边界必须同源
`@fastify/multipart` 每次生成新 boundary——测试里 headers 和 payload 必须取自**同一次**构造调用的结果，分开取必挂。

### 13. update 归一化字段再校验的坑
`plans.validate()` 二次校验时，库里归一化成 JSON 字符串的 features 会被 merge 回来当成一整行 token。校验逻辑要识别 `[` 开头的 JSON 数组。

### 14. SQL 占位符数量
发码加列后单发/批量两条 INSERT 都少过 `?`（`18 values for 19 columns`）。改表结构后跑 `test-license.js` / `test-license-pool.js`。

### 15. seed 复活（2026-11-04）
演示商品/统计的「是否已种」判定如果只看表空不空，清空数据后 seed 会复活。判定必须看 `settings.seed_*` 标记 + 建表前的 `isFreshDb`。


### 16. DELETE 带 `Content-Type: application/json` 但没 body → 全站删除按钮 400（2026-11-05）
前端请求封装无条件加 `Content-Type: application/json`，`del()` 又没有 body。Fastify 5 直接判
`FST_ERR_CTP_EMPTY_JSON_BODY`，表现是「删除产品/授权/设备/版本全部报 BadRequest」。
两层修：① 前端只有真有 body 才声明 JSON 头；② 服务端注册 `application/json` 解析器，空 body 当 `{}`（兜住旧缓存页面和第三方调用）。

### 17. manifest 的版本字段叫 `latest`，不是 `version`
把 `manifest()` 的返回值直接丢给日志函数时，`rec.version` 是 undefined —— 去重键绑不上，
同一台机器每次轮询都插一条。要么显式 `rec.version || rec.latest`，要么别复用响应对象当记录。


### 18. 微信网页授权 redirect_uri 的域名约束（2026-11-05）
公众号网页授权的 `redirect_uri` 必须落在「网页授权域名」下，**只接受域名（80/443 端口），
不能带 `https://`、路径或端口**。子路径部署（`/platform/api/wechat/oauth/callback`）没问题——
微信只看域名，不看路径。报 `redirect_uri 参数错误` 十有八九是域名没配或填法不对。

### 19. 静默授权（snsapi_base）拿不到昵称头像
`snsapi_base` 只回 openid，不回资料。补救：**已关注**公众号的用户可以用普通接口
`/cgi-bin/user/info` 拿昵称头像（网页授权前后都可以）；没关注的只能显示「用户XXXX」。
要昵称就选 `snsapi_userinfo`，代价是首次弹一次授权确认页。

## 数据与安全

### 16. 额度包商品必须充 `users.blcloud_quota`
`api_keys` 是遗留表，用户端不展示——充到那里等于付了钱没发货（2026-11-01 线上踩过）。「已支付」≠「已发货」，发货结果写 `orders.deliver_result`。

### 17. 解绑/吊销授权必须同时作废 `client_sessions`
否则客户端拿旧 token 继续白嫖。会话作废统一返回 401 `SESSION_REVOKED`（区别于过期 `UNAUTHORIZED`），客户端要能分辨「被解绑」和「该刷新令牌」。

### 18. 离线票据用 Ed25519，不用 HMAC
HMAC 密钥必须进客户端=可伪造。私钥在 `data/offline-signing-key.json`，验签用原始 payload 字符串，`iat`/`exp` 双校验防时钟回拨。

### 19. `data/.appsecret` 是 AES 主密钥
丢失即所有加密配置不可解。备份/恢复必须与 `app.db` 同批。

### 20. 微信支付新商户号用「微信支付公钥」
2024 年起新商户号拉不到 `/v3/certificates`。典型症状：下单成功、查单成功、**只有回调一直失败**（下单只用商户私钥签名）。配置自检用 `wxpay.testConfig()`，无需真付款。

### 21. 支付渠道未开通不得降级为模拟支付
会 0 元发货。`/api/wechat/simulate/*`、`/api/pay/simulate/*` 是演示后门，生产必须关闭（`NODE_ENV=production` 时默认关）。

### 22. 授权码只有一种格式
`genLicenseKey()` → `LIC-XXXXXXXX-XXXXXXXX-XXXXXXXX`。支付发放和后台手工发放都必须用它，别自己拼。

## blcloud 物联（ThingsBoard）开户

### 23. 建档 ≠ 能登录
TB 没有管理员设密码接口，必须走激活：建档 `?sendActivationMail=false` → `GET /api/user/{id}/activationLink`（**Accept 必须 text/plain，否则 Spring 406**）→ 取 `activateToken` → `POST /api/noauth/activate` → 真实登录终检。开通类流程必须以真实登录做终检。

### 24. TB 登录响应里没有 userId
只有 token/refreshToken，userId 要从 JWT 里解。

## 环境与部署

### 25. npm 安装必须加 `--cache <项目内路径>`
默认缓存目录权限被拒。

### 26. better-sqlite3 是原生模块
Windows 的 node_modules 不可直传 Linux，必须服务器本地 `npm ci`。服务器 Node v24 不要降级。

### 27. 本地探测 HTTP 必须加 `--noproxy '*'`
否则走系统代理误报 502。

### 28. PM2 陷阱
`pm2 restart --update-env` **不会**读入 ecosystem 配置里新增的 env（PM2 7.0.4 实测）。改了 `BASE_PATH` 必须 `pm2 delete blcloud-admin && pm2 start deploy/ecosystem.config.cjs && pm2 save`。查 env 用 `pm2 env <id>`（不接受进程名）。

### 29. nginx 子路径
`location` 必须写 `^~ /platform/`（官网的正则 location 会抢静态资源），`proxy_pass` 末尾**不能带 `/`**（带了前缀被剥掉）。生效验证：`/platform/api/health` 200 且 `/api/health` 404。

### 30. SQLite 只能单实例
禁止 PM2 cluster 模式。反代下要 `TRUST_PROXY=1` 才拿得到真实 IP。

## 测试约定

- 每修一个坑，尽量在 `tools/test-*.js` 加回归断言（本文件提到的 `test-subpath.js`、`test-ui-layout.js` 都是这么来的）。
- 备份类测试用独立 `DB_PATH`/`BACKUP_DIR`，别污染真实目录。
- 支付测试每次新建订单（同商户号 out_trade_no 不可重复）。
