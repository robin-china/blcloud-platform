# 踩坑记录

> 每条都是线上/本地真实踩过的，不是理论风险。改代码前先扫一眼相关章节。
> 新坑按「日期 + 现象 + 根因 + 修法」追加到对应章节末尾。

## 前端（Vue 无打包静态页）

### 1. in-DOM 模板禁止自闭合自定义组件标签
`<page-xxx />` 会把后续所有兄弟节点吞进组件里，页面直接缺一大块。必须显式写 `<page-xxx></page-xxx>`。

### 2. 页面脚本必须用 IIFE 包裹
禁止顶层 `const { ref } = Vue`——多个页面脚本共用全局词法作用域，重复声明会让**后续整个脚本失效**（不是只坏当前页）。

### 3. Vue 模板里禁止引用全局变量（2026-10-31 支付二维码崩过）
Vue 3 浏览器编译的模板只从 setup/data/props/`app.config.globalProperties` 找标识符。即使 `window.U` 存在，模板里 `U.basePath` 也是 undefined。需要就在 setup 里 `return` 出来；两端 App 已注册 `app.config.globalProperties.U = window.U` 兜底。注意：脚本里拼 HTML 字符串给 `v-html` 不受此限。

### 4. 原生 confirm 在内嵌浏览器被静默禁用（2026-11-04）
`confirm()` 返回 false 且无报错 → 删除操作「点了没反应」。统一用 `U.confirm()`（自绘确认框），删除类操作必须 try/catch + `U.failMsg()` 把错误显出来。

### 5. 模板 `:value` 里禁止写 `join('\n')`
模板字面量把 `\n` 求值成真换行，Vue 编译直接 SyntaxError。换行在 setup 里拼好（computed）再给模板。授权类页面踩过。

### 6. `.field label { display:block }` 压掉开关的 inline-flex（2026-11-05）
`ui.css` 里 `.field label` 优先级 (0,1,1) > `.switch` 的 (0,1,0)。凡在 `.field` 里的 `<label class="switch">` 被强制 block，`<span class="track">` 退化成 inline——宽高/背景全失效，轨道消失，只剩白色圆钮叠在文字上。修法：声明写成 `.switch, label.switch`（同优先级靠后者胜），`.track` 加 `display:inline-block; flex:none` 兜底。`test-ui-layout.js` 有断言守护。

### 7. 共用图标走 `U.icons` / `U.svgIcon()`
不要在各文件重复定义 ICONS。

## 后端（Fastify + better-sqlite3）

### 8. 子路径部署下所有 URL 拼接必须带斜杠意识
- `basePath()` 返回 `/platform` **无尾斜杠**，手写 `basePath() + 'user/'` 会拼出 `/platformuser/`（推广链接线上 404 过）。拼接用 `publicUrl(req, pathname)`，它自动补前导斜杠。
- `req.url.startsWith('/api/...')` 判定必须带 `basePath()`，否则子路径部署失效（微信支付回调栽过）。

### 9. 无斜杠目录 URL 会 404 掉整页资源（2026-11-05）
新版 @fastify/static 对 `/platform/admin`（无尾斜杠）**直接 200 返回 HTML，不再重定向**。页面里相对路径 `../assets/ui.css`、`js/app.js` 按无斜杠基准解析 → 全 404 → 样式丢失、脚本不执行、开关「不可操作」。修法：`server/index.js` 加 onRequest 钩子，public 下有 index.html 的目录无斜杠一律 301 补斜杠（保留查询参数）。`test-subpath.js` 有断言守护。

### 10. Fastify 5 的 redirect 签名是 `redirect(url, code)`
不是老版的 `(code, url)`。写反了会报 `Called reply with an invalid status code`。

### 11. Node 内置 fetch 会自动补默认头
对接第三方 API（微信支付 v3 实测）时，凡对方可能校验的头（accept-language、sec-fetch-mode 等）都**显式写死**，别依赖默认值。

### 11b. 微信公众号 API 裸 fetch → 空响应「Unexpected end of JSON input」（2026-11-08 线上踩过）
条目 11 的第二次现身：网页授权 `oauthAccessToken()` 等对 `api.weixin.qq.com` 全是裸 `fetch(url)`，
线上真实环境一直报「网页授权失败：Unexpected end of JSON input」——内置 fetch 补的
`accept-language: *` 等头让微信直接回空 body，`res.json()` 炸掉。**本地测试环境复现不了**（同一代码测试桩里是好的），只有线上真实微信接口才暴露。
修复：`server/services/wechat.js` 统一走 `wxFetch()`——显式写死 `Accept/Accept-Language/User-Agent`，
并用 `text()` + 手动 parse，空/非 JSON 响应报出 HTTP 状态码和原文片段。
教训：**所有对外 HTTP 调用必须过统一的带请求头封装**，`res.json()` 换成 text+parse 才能拿到可排障的报错。

### 11c. 授权接口路径写成 `/snsapi/…` → 微信 404 空 body，报错炸在 30 行外（2026-11-08 线上踩过）
完整剧情分三幕，每一幕都比上一幕更迷惑：
1. 裸 fetch 报「Unexpected end of JSON input」→ 以为是条目 11 的请求头问题（方向错了，真因是路径）；
2. 补上请求头后变成 `Cannot read properties of undefined (reading 'slice')` —— errcode 没给、openid 也没有，
   一路炸到建号兜底 `` `用户${openid.slice(-4)}` ``，报错位置和真实原因隔了整条回调链路；
3. 加了「缺 openid 抛脱敏原始响应」的诊断后，看到 `{}｜HTTP 404` 才真相大白：
   **换 token 接口路径是 `/sns/oauth2/access_token`，`snsapi` 只是 scope 名的前缀**，
   写成 `/snsapi/…` 微信直接 404 且空 body（`/sns/userinfo` 同理，`/snsapi/userinfo` 也是 404）。
   本机 curl 一测立刻实锤：错误路径 404 LEN:0，正确路径回 JSON errcode。
修复：两处路径改正；换 token 后先校验响应必须含 openid（缺失时带 HTTP 状态码抛脱敏原始响应）；
`ensureUser` 建号兜底改 `String(openid||'')` 防御；回调 catch 把 `e.stack` 前两行留进诊断。
教训：**「空 body + 无报错」先 curl 一下接口本身**，别急着往请求头/网络玄学上猜——
404 空 body 伪装成了「微信挑请求头」的样子；边界数据第一站验形 + 诊断带 HTTP 状态码，两层缺一不可。

### 12. multipart 测试边界必须同源
`@fastify/multipart` 每次生成新 boundary——测试里 headers 和 payload 必须取自**同一次**构造调用的结果，分开取必挂。

### 13. update 归一化字段再校验的坑
`plans.validate()` 二次校验时，库里归一化成 JSON 字符串的 features 会被 merge 回来当成一整行 token。校验逻辑要识别 `[` 开头的 JSON 数组。

### 14. SQL 占位符数量
发码加列后单发/批量两条 INSERT 都少过 `?`（`18 values for 19 columns`）。改表结构后跑 `test-license.js` / `test-license-pool.js`。

### 15. seed 复活（2026-11-04）
演示商品/统计的「是否已种」判定如果只看表空不空，清空数据后 seed 会复活。判定必须看 `settings.seed_*` 标记 + 建表前的 `isFreshDb`。


### 16. DELETE 带 `Content-Type: application/json` 但没 body → 全站删除按钮 400（2026-11-05）
前端请求封装无条件加 `Content-Type: application/json`，`del()` 又没有 body。Fastify 5 直接判
`FST_ERR_CTP_EMPTY_JSON_BODY`，表现是「删除产品/授权/设备/版本全部报 BadRequest」。
两层修：① 前端只有真有 body 才声明 JSON 头；② 服务端注册 `application/json` 解析器，空 body 当 `{}`（兜住旧缓存页面和第三方调用）。

### 17. manifest 的版本字段叫 `latest`，不是 `version`
把 `manifest()` 的返回值直接丢给日志函数时，`rec.version` 是 undefined —— 去重键绑不上，
同一台机器每次轮询都插一条。要么显式 `rec.version || rec.latest`，要么别复用响应对象当记录。


### 18. 微信网页授权 redirect_uri 的域名约束（2026-11-05）
公众号网页授权的 `redirect_uri` 必须落在「网页授权域名」下，**只接受域名（80/443 端口），
不能带 `https://`、路径或端口**。子路径部署（`/platform/api/wechat/oauth/callback`）没问题——
微信只看域名，不看路径。报 `redirect_uri 参数错误` 十有八九是域名没配或填法不对。

### 19. 静默授权（snsapi_base）拿不到昵称头像
`snsapi_base` 只回 openid，不回资料。补救：**已关注**公众号的用户可以用普通接口
`/cgi-bin/user/info` 拿昵称头像（网页授权前后都可以）；没关注的只能显示「用户XXXX」。
要昵称就选 `snsapi_userinfo`，代价是首次弹一次授权确认页。

## 数据与安全

### 16. 额度包商品必须充 `users.blcloud_quota`
`api_keys` 是遗留表，用户端不展示——充到那里等于付了钱没发货（2026-11-01 线上踩过）。「已支付」≠「已发货」，发货结果写 `orders.deliver_result`。

### 17. 解绑/吊销授权必须同时作废 `client_sessions`
否则客户端拿旧 token 继续白嫖。会话作废统一返回 401 `SESSION_REVOKED`（区别于过期 `UNAUTHORIZED`），客户端要能分辨「被解绑」和「该刷新令牌」。

### 18. 离线票据用 Ed25519，不用 HMAC
HMAC 密钥必须进客户端=可伪造。私钥在 `data/offline-signing-key.json`，验签用原始 payload 字符串，`iat`/`exp` 双校验防时钟回拨。

### 19. `data/.appsecret` 是 AES 主密钥
丢失即所有加密配置不可解。备份/恢复必须与 `app.db` 同批。

### 20. 微信支付新商户号用「微信支付公钥」
2024 年起新商户号拉不到 `/v3/certificates`。典型症状：下单成功、查单成功、**只有回调一直失败**（下单只用商户私钥签名）。配置自检用 `wxpay.testConfig()`，无需真付款。

### 21. 支付渠道未开通不得降级为模拟支付
会 0 元发货。`/api/wechat/simulate/*`、`/api/pay/simulate/*` 是演示后门，生产必须关闭（`NODE_ENV=production` 时默认关）。

### 22. 授权码只有一种格式
`genLicenseKey()` → `LIC-XXXXXXXX-XXXXXXXX-XXXXXXXX`。支付发放和后台手工发放都必须用它，别自己拼。

## blcloud 物联（ThingsBoard）开户

### 23. 建档 ≠ 能登录
TB 没有管理员设密码接口，必须走激活：建档 `?sendActivationMail=false` → `GET /api/user/{id}/activationLink`（**Accept 必须 text/plain，否则 Spring 406**）→ 取 `activateToken` → `POST /api/noauth/activate` → 真实登录终检。开通类流程必须以真实登录做终检。

### 24. TB 登录响应里没有 userId
只有 token/refreshToken，userId 要从 JWT 里解。

## 环境与部署

### 25. npm 安装必须加 `--cache <项目内路径>`
默认缓存目录权限被拒。

### 26. better-sqlite3 是原生模块
Windows 的 node_modules 不可直传 Linux，必须服务器本地 `npm ci`。服务器 Node v24 不要降级。

### 27. 本地探测 HTTP 必须加 `--noproxy '*'`
否则走系统代理误报 502。

### 28. PM2 陷阱
`pm2 restart --update-env` **不会**读入 ecosystem 配置里新增的 env（PM2 7.0.4 实测）。改了 `BASE_PATH` 必须 `pm2 delete blcloud-admin && pm2 start deploy/ecosystem.config.cjs && pm2 save`。查 env 用 `pm2 env <id>`（不接受进程名）。

### 29. nginx 子路径
`location` 必须写 `^~ /platform/`（官网的正则 location 会抢静态资源），`proxy_pass` 末尾**不能带 `/`**（带了前缀被剥掉）。生效验证：`/platform/api/health` 200 且 `/api/health` 404。

### 30. SQLite 只能单实例
禁止 PM2 cluster 模式。反代下要 `TRUST_PROXY=1` 才拿得到真实 IP。

### 31. in-DOM 模板首屏会闪一堆 `{{ }}`，而且不能用 `v-cloak`（2026-11-08）
前后台都是 in-DOM 模板（`{{ }}` 直接写在 `index.html` 里），Vue 挂载前浏览器就把花括号当文本渲染，
网速一慢/脚本一多就能看到满屏占位符。标准解法是 `v-cloak`，但**这里不能用**：
`mount('#app')` 是把 `#app` 的 innerHTML 当模板，`#app` 自己不在编译范围内 ——
写在上面的 `v-cloak` 永远不会被移除，页面会永久隐藏。
正确做法：`<head>` 里**内联** `#app{display:none}` / `#app.ready{display:block}`，
挂载成功后 `classList.add('ready')` 并移除加载遮罩；再加一个 10 秒兜底把遮罩变成「点击刷新」，
否则某个脚本报错时页面会永远停在「加载中」而不是白屏（白屏至少能看出是挂了）。
内联是必须的：外链 CSS 要等下载，等到的时候花括号早就闪过去了。

### 32. 未付款订单删除只能软删除（2026-11-08）
「删掉没付的订单」听起来就是一条 DELETE，但支付二维码可能**已经渲染给用户了**，
他过半小时才扫。记录真删掉，微信回调打回来 `SELECT * FROM orders WHERE order_no = ?` 查不到，
钱进了商户号、订单和货都没有 —— 这种故障没法自愈，只能人工对账。
所以用的是 `deleted_at` / `deleted_by` 软删除：列表过滤掉，`markPaid()` 命中时顺手清空标记把订单复活，
并在支付诊断里留一条「该订单曾被删除，收到回调后已恢复」。
顺带两个容易漏的点：① 下单用积分抵过现的，删除必须退回积分（`points_logs` 留痕）；
② 仪表盘「待付款」计数、后台状态筛选都要带 `deleted_at IS NULL`，否则删了还在报警。

### 33. 授权响应「缺字段 / null」的语义被推翻了两次（LabelGo 契约 v1/v2）
删了授权码，客户端仍显示「在线授权」：服务端回的是 `valid:false` + 中文 reason，
但**没有 `license` 字段**。客户端把「响应里没有 license」当成「老后台、没给结论」，
于是沿用上次的权益快照 —— 校验失败也白搭。
修法：`verify` / `heartbeat`（以及扫码登录、手机号登录、refresh 等所有会给权益结论的响应）
**永远带 `license` 字段**，有效=完整对象、其余=`null`；失败时 `reason`/`code` 用标准枚举码，
中文挪到 `message`，并带 `entitlement_changed:true` 让客户端立刻清快照。
另外两个连带的坑：
- 免费档 `plan_name` 必须写死「免费版」（后台原名放 `plan_display_name`），
  默认种子叫「在线免费版」，客户端按字面判断会以为还是在线付费档。
- 给无档位的历史授权补齐 `plan_name`（防止客户端回退显示「在线授权」）之后，
  **离线票据里 `!!ent.plan_name` 不能再用**来判断「有没有档位」——
  历史授权会被误判成有档位，离线宽限从 3 天缩到 2 小时（`test-license-pool.js` 当场抓到）。
  判断要直接问 `plans.licensePlan(lic)`。
- 部署故障只能 `5xx`：`403` 在客户端语义里是「授权没了」，会把付费客户降成免费版。
- 续费 / 升级的 UPDATE 原先没清 `downgraded_from` / `downgraded_at`：
  降级过的用户续了费，`license_payload` 仍带「已降级」痕迹，客户端一直提示订阅到期，
  `entitlementVersion` 还把它算进哈希导致版本号对不上。两条发货 SQL 都要一起清空。

**v2 反转（2026-11-09，软件方改了客户端判定）**：`license:null` / `{}` / 字段省略
一律改成「后台没给结论 → 沿用旧快照、**不降档**」，只有同时带 `license_revoked:true`
才算明确撤回。v1 第 3 条的 `valid:true + license:null = 明确无授权` 直接变成**禁止写法**——
照它写，删了码客户端根本不会降档；而客户端按 v1 处理时，一次正常刷新又会把所有在线授权
清成免费版（后台不下发完整 license 就再也同步不回来）。同一个字段，两版含义完全相反。
- 删掉 `noLicense()`；账号无授权也回 `200 + valid:false + NO_LICENSE + license_revoked:true`。
- `reason` 改契约短码（`REVOKED` / `EXPIRED` / `INACTIVE` / `NO_LICENSE` / `MACHINE_NOT_BOUND`），
  `code` 保留内部完整码；中文只在 `message` / `reason_text`。原来断言 reason 含中文的测试要改。
- 授权级失败统一 200（v1 用 403）；**401 / 5xx 的 body 不能带 `valid:false` 或 `license` 字段**，
  否则客户端按状态码该保留快照、按 body 又清快照。
- 心跳**不能复用 `requireClient`**：它把「解绑 / 吊销」的 `SESSION_REVOKED` 也回成 401，
  而 v2 规定 401 不降档 → 验收「不点刷新等一拍心跳自动降」永远过不了。心跳改成自己判会话，
  撤销时回 200 + `MACHINE_NOT_BOUND`，`code` 仍留 `SESSION_REVOKED` 给老客户端提示重新激活。
- 教训：**跨端契约的字段语义以客户端当前判定为准**，后台不能抱着上一版文档实现；
  这种反转要有静态守护断言（「禁止任何 `valid:true + license:null` 响应」）才不会改回去。

## 34. 登录态有三份副本 + 401 一刀切（2026-11-10）

「已经登录却显示要登录的界面 / 顶栏登录按钮闪一下 / 页面弹请先登录」不是单点 bug，
是三套登录态数据源不同步叠加出来的：

- **三份副本**：Vue 根 `state.token/user`（顶栏/菜单用）、`localStorage.user_token`
  （各子页面守卫各自读）、`U.api.getToken()`（请求头用）。任何一处单独清/不清都撕裂。
- **401 一刀切**（旧版 api.js）：任何接口 401 都清 token 并把 `location.hash` 改成
  `#/login` —— 管理后台根本没有 `#/login` 路由，`syncHash` 把 route 设成 `login`
  后主内容区整片空白；开放接口业务 401（带 `code`，如 KEY_INVALID）也会误清网页登录态。
- **loadMe 失败即未登录**：`/me` 网络抖动 / 5xx 也清 `state.token`（admin 端还不清
  localStorage）→「一会儿要登录、刷新又好了」。
- **免登竞态**：handoff 换票是异步的，子页面 `onMounted` 同步读 localStorage 时票据
  还没换成 token → 抢先跳 `#/login`，随后 `replaceState` 把错误地址固化，刷新也回不去。

修复约定（后续页面照此写，别再各查各的）：

- api.js：401 区分三类 —— 登录接口自身 401 / 带 `code` 的业务 401 / 真过期（只有
  `error` 无 `code`）。只有最后一类清 token 并派 `app:unauthorized` 事件，
  **绝不直接改 hash**。两端 app.js 监听该事件同步 state（后台切登录页、用户端
  私密页跳登录、公开页只 toast）。
- `U.authReady()` / `U.setAuthReady()`：根组件校验完登录态后 resolve，子页面守卫
  一律 `if (!(await U.authReady())) { location.hash = '#/login'; return; }`，
  不再同步读 localStorage。
- `loadMe()` 只在 `e.status === 401` 时清登录态；其它错误保留（顶栏不掉线）。
- 首屏遮罩等 `app:ready` 事件再撤（mount 前注册监听）；兜底超时改强制显示页面，
  不再逼用户点刷新；mount 抛错也必须给 `#app` 加 `ready`，否则整页只剩遮罩。

## 35. 补发授权「点了没反应」与重复发货（2026-11-10）

- 前端 `deliver()` 既无 try/catch 也无 `load()`：接口 400/500 直接变成未捕获
  rejection，零反馈；成功了列表也不刷新。同页其它按钮都有 catch，唯独它没有。
- 后端 `deliverOrder()` 不幂等：purchase 单每次重发一张授权码 / 重充一次额度 /
  再加一次销量；**续费单每次叠加一年有效期**。而后台 `deliverText()` 只认
  `api_quota/license/device` 三种类型，续费/升级单（`license_renew/license_upgrade`）
  发完货仍显示红色「未发放任何内容」→ 管理员以为没发成功反复点 → 每点一次 +365 天。
- 修复：补发接口默认 409 `ALREADY_DELIVERED`（幂等闸），前端确认后带 `force=1`
  重发；`deliverOrder` 抛错回 400 带中文原因（不再 500 静默）；`deliverText`
  与用户端对齐补齐 5 种类型；写 `admin_logs` 审计。**「续费/升级单的发货结果是
  对原授权的 UPDATE，不是 INSERT」—— 所有展示发货内容的地方都要认这两种 type。**

## 36. 升级结果上报契约「以后台为准」一次定稿（2026-11-10）

软件端问 5 个问题（路径/鉴权/字段名/失败码/去重），后台不能让客户端猜字段。
逐条定稿：

- **接口** `POST /api/open/v1/app/update-report`——上一轮做升级记录时已埋了最小版，
  客户端建议的路径正好和现有的一致，不用改名。
- **鉴权：不鉴权**（与清单接口同一逻辑）：上报发生在登录前 / 升级中断场景，令牌状态
  不可靠；只写流水不改业务状态，被刷最多表变大。别为了「看起来安全」加签名——
  密钥随安装包分发等于没有鉴权，只会把「上报 404」换成「401」。
- **字段名全 snake_case**，与客户端草案逐字一致（machine_code/from_version/to_version/
  result/code/stage/duration_ms/elevated/os/at）；服务端兼容旧字段 machine/from/status。
- **失败码细分**：整数 code + 阶段 stage 两列（app_update_log 迁移新增
  result_code/stage/duration_ms/elevated/os_info/client_at 六列）。
  code：0 成功；3 已提权仍不可写；4 旧进程结束不掉；5 覆盖失败；6 新版本未起来；
  7 UAC 被取消；8 launch_failed（三兜底全挂）。
- **去重 = 覆盖不累加**：同 machine+from→to 只留最新一条结果。客户端本地重试 7 天、
  回滚重升都会重复 POST，累加会把失败数灌水、成功率统计作废。check 流水不受影响。
- rollback 是独立 action（不是 fail 的别名），后台升级记录页有单独筛选和汇总。

## 37. 发售前保护：密钥进客户端 = 没有密钥（2026-11-11）

对接单里最要命的一条是「客户端源码/备份里出现过 appSecret」。这条不解决，
后面加多少签名都是装饰。处理顺序必须是「先让旧通道继续能用 → 再删客户端密钥 → 最后关旧通道」，
反过来做等于给第一批客户制造一次全量 401。

- **双模不是两套代码**：`resolveApp()` 一个入口按可靠性降序选身份
  （有效 Bearer → 四件套签名 → 仅 x-app-key），登录前端点三种都放行。
  已登录用户带过期令牌时自动落到签名/公开模式 —— 否则「令牌过期」会连激活都做不了。
- **旧密钥必须并存**：`app_secret_prev` + `legacy_hmac` 开关。直接覆盖 `app_secret`
  是最容易写的实现，也是最容易造成事故的：没有回滚窗口。
  关闭旧通道时回 `APP_SECRET_RETIRED`，客户端才能分辨「该升级」和「密钥配错了」。
- **`auth_mode` 必须落表**：内存计数一重启就没了，而「旧 HMAC 归零」是关通道的唯一依据。
  只记 path/mode/status，不记 body（body 里是授权码和机器码）。
- **公开模式不是关掉鉴权**：频控 + 写请求强制 nonce + 业务闸门（授权码绑定、验证码次数）
  一个都不能少；它的价值只是「不再把共享密钥发给所有人」。
- **清单签名要签每一次响应**，不能发布时签一次静态文件：`rollout` / `mandatory` /
  `server_time` 都是随请求变的，静态签名会把「这台机器是否命中灰度」签成发布那一刻的样子。
  静态兜底也要签，否则改 DNS 指向静态文件就是一条免验签的安装通道。
- **`kid` 要进签名内容**：否则攻击者可以换 kid 诱导客户端用另一把公钥（或直接跳过验签）。
- **换票必须有 `seq` + `epoch`**：只有 `exp` 的话，「停票」对已发出的票无效，
  机器被退/被转卖后还能用到票过期。停票 = epoch+1，老票整批作废；客户端必须持久化最大 seq，
  收到更小的 seq 就是重放。
- **黄金向量要固定样本**：两边各自挑一份「随手写的清单」算哈希，永远对不上。
  文档里钉死样本 + canonical 长度 + sha256，两端跑同一份才算对齐。
- **权益快照要单独一把密钥**：清单公钥最容易从安装包里挖出来，用它签权益等于把
  「解锁全部功能」的钥匙一起交出去。三把密钥（清单/权益/离线票据）互不复用。
