## 1. 接收的任务清单（转成后台交付物）

| 阶段 | 交付物 | 验收点 |
|---|---|---|
| P1 | 数据表 `market_templates` / `market_purchases` / 枚举字典；`GET /market/meta`、`GET /market/list`（游标分页）、`GET /market/detail/:id` | 筛选 4 维（行业/纸类型/宽高/关键词）+ 4 种排序 + 默认 limit=50 + 游标不漏不重；列表与详情**都不含 fileUrl** |
| P1 | 后台「枚举字典管理」页、「模板上下架」页（含 .blls 与缩略图上传、price/status/author） | 运营改完字典，`/market/meta` 立即生效，无需发客户端版本 |
| P3 | `POST /market/redeem`（事务原子扣积分、已购免重复扣）、`GET /user/credits`、`POST /user/signin`、一次性 5 分钟下载短链 | 积分单一真相源在 `users.points`；并发兑换不超扣；短链过期/重放无效；`fileSha256` 下发 |
| P4 | `GET /market/owned`、`downloads` 热度累加、搜索增强、UGC `author` 预留 | 已购可重复下载且不再扣分 |

配套：同 machine_code 高频兑换限流/告警、`points_logs` 流水、`admin_logs` 审计、备份清单纳入
新表与私有文件目录、测试脚本（接口 + 游标分页 + 并发扣减）。

## 2. 现有能力盘点（哪些是复用、哪些是真新建）

**可直接复用**
- 公开读/写鉴权框架（C 批）：`resolveApp` 三模式、`x-app-key` 公开模式、IP/app 频控、nonce 防重放。
- 用户会话 `requireClient`：`session.machine_id` 与 `/license/ticket` 同一机器码口径，已购归属直接接着用。
- 积分单一真相源：`users.points` + `points_logs` 流水已存在；订单抵扣、退款回退、blcloud 额度兑换都走它。
- 签到：网页端 `POST /api/portal/signin` 已有「每日 +10」（设置项 `user_points_signin`），开放接口侧补一层同口径即可。
- 事务：better-sqlite3 同步事务，原子扣减天然可做。
- 后台上传：`/api/upload`（图片白名单）+ Nginx `/platform/uploads/` 直出，缩略图可直接用。
- 后台页面框架：Vue 3 in-DOM 静态页 + 菜单注册 + 审计日志，新增两个页面成本可控。

**需要新建 / 改造**
- 三张新表 + 游标分页索引（`(sortKey, id)` 联合，禁 offset 深翻页）。
- `.blls` 上传通道：**现 `/api/upload` 只收 jpg/png/webp/gif**，且 `/platform/uploads/` 是 Nginx 直出目录 ——
  模板文件**不能**放这里（会绕过一次性短链）。需落私有目录（如 `data/market/`），只经后端签发
  短链下载；缩略图仍走公开上传。
- 一次性短链：生产**没有 CDN**（现有升级包也是本地磁盘 + Nginx 直出）。短链由后端用现有 AES 主密钥
  做 HMAC 签名（路径 + 5 分钟过期 + 单次/绑定 machine），不依赖 CDN 即可满足「防盗链」。
- Bearer 写接口强制 `x-nonce`：现网 `requireClient` 分支**不校验 nonce**（只有公开模式写请求校验），
  按清单「写与扣积分必须 Bearer + x-nonce」需要补一道，属小改造。

## 3. 需要拍板的口径（Q1~Q4 不阻塞 P1，Q5 影响数据模型，建议早点定）

| # | 问题 | 我方建议 / 现状 |
|---|---|---|
| Q1 | **积分单位**：清单里 `price` 的「所需积分」是否等于 `users.points` 原始分？现网 100 分 = ¥1 订单抵扣额度，且 blcloud 额度兑换也按分扣 | 默认按 `users.points` 原值直接扣，不做换算；请确认模板定价量级（如 10 分 / 100 分） |
| Q2 | **新用户 +200**：清单说「沿用后台现有用户中心积分口径」，但现网新用户 `points = 0`，**没有 +200 发放** | 若保留此规则需新增发放点（注册时 +200 并记流水）；请确认是本次补上，还是清单描述有误 |
| Q3 | **已购归属按机器还是按账号**：清单数据模型写「机器码为准」，但 `/market/owned` 又写「本 machine 已购」 | 建议**资产归 user_id**（换机/重装不该丢已购模板），machine_code 仅做归属记录与防刷；若坚持按机器，用户换机后要重新扣分，请书面确认 |
| Q4 | **downloads 统计**：清单写「兑换成功 +1」，已购重复下载是否累加 | 建议只首次兑换 +1，重复下载不累加（否则刷热度）；请确认 |
| Q5 | **签到日切时区**：现网按 UTC 日期判重，北京时间 00:00–08:00 会误报「今天已签到」 | 我方顺手改成北京时间日切，并把网页端与开放接口签到统一到同一份幂等判定 |
| Q6 | **CDN**：清单写「缩略图/文件走 CDN」 | 生产无 CDN，按上面「私有目录 + 后端短链」实现即可满足防盗链；若确需真 CDN，请给域名/密钥/回源方案 |

另有三点我方按清单直接执行、无需再确认：列表/详情不返 `fileUrl`；`fileSha256` 随兑换下发由客户端强校验；
机器码与 `/license/ticket` 同口径（redeem 传的 `machine_code` 与会话 `machine_id` 不一致将回
`403 MACHINE_MISMATCH`，沿用现有错误码）。

## 5. 风险提示（先说清楚，免得后面返工）

1. **客户端的本地积分只能当缓存**：`credits.json` 以服务端 `GET /user/credits` 为准；离线期间不要允许
   离线兑换，否则一定出现双花。
2. **已购重复下载要防重放**：短链必须绑定 template + machine + 5 分钟 TTL，且不能靠客户端自觉。
3. **游标排序键会变**：`downloads` 每次兑换都自增，按热度翻页时可能重复/漏项；这是清单里
   `(sortKey,id)` 游标也解决不了的固有问题，建议热度榜按「快照 top N」或接受轻微抖动。
4. **P1 管理页会涉及新文件类型**：`.blls` 是加密二进制，Nginx 侧必须确保私有目录不被静态映射，
   否则短链形同虚设（这条会进上线检查清单）。
