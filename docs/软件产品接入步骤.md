# 新软件产品接入操作手册

> 面向运营/管理员。全程在管理后台可视化操作，无需改代码。
> 后台入口 `/admin/`，用户端入口 `/user/`。

---

## 总览

| 步骤 | 操作位置 | 产出 |
|---|---|---|
| 1 建立产品档案 | 产品管理 | 产品记录（含 product_id） |
| 2 推到用户端首页 | 官方上架 | 商城首页可见 |
| 3 发接入凭证 | 开放接口 | app_key / app_secret |
| 4 产生授权码 | 用户端商城 或 授权管理 | LIC-XXXXXXXX-XXXXXXXX-XXXXXXXX |
| 4.5 配置套餐档位 | 套餐档位（顶部下拉选中本应用） | 该软件产品专属的一套档位 |
| 5 客户端激活 | 软件端调用开放接口 | access_token |
| 6 上线运营 | 开放接口 / 授权管理 / blcloud 调用 | 会话、续期、升级 |

依赖顺序：**3 依赖 1**（应用要绑定产品）；**4.5 依赖 3**（档位挂在应用上）；**5 依赖 3 和 4**。
一个软件产品 = 一个上架商品 + 一个开放应用 + 一套专属档位；未来上架新产品时重复这套流程，不要复用别的产品的档位。

---

## 步骤 1 · 建立产品档案

**路径：产品管理 → 新建产品**

| 字段 | 说明 | 必填 |
|---|---|---|
| 产品名称 | 如「花盆卫士 PC 客户端」 | 是 |
| 产品类型 | 选「软件」（另有硬件 / 服务） | 是 |
| 副标题 | 列表和商城卡片上的一句话卖点 | — |
| 分类 | 如「智慧农业」 | — |
| 售价 / 原价 | 下单金额取「售价」；原价用于划线展示 | — |
| 库存 | 软件类可填大数或 0（不校验库存时随意） | — |
| 版本号 | 与安装包实际版本一致，如 `1.0.0` | — |
| 产品图标 | 上传图片，建议 256×256 PNG | — |
| 下载地址 | 安装包 URL（对象存储直链或 CDN） | — |
| 产品简介 | 详情页正文 | — |
| 功能亮点 | 每行一条，详情页渲染成列表 | — |
| 状态 | 选「上架」 | 是 |
| 排序 | 越大越靠前 | — |

保存后在列表里记下这条产品，**第 3 步绑定产品时要用**。

> 图标、详情页内容直接决定用户端商城的观感，正式上线前务必补齐。

---

## 步骤 2 · 推到用户端首页

**路径：官方上架**

- 列表只显示 `is_official=1` 的产品
- 点「设为推荐」→ 出现在用户端商城首页；再点「取消推荐」移出
- 「上移 / 下移」调整首页顺序
- 「下架 / 上架」切换售卖状态

价格不在这里改，回「产品管理」编辑。

---

## 步骤 3 · 发软件端接入凭证

**路径：开放接口 → 新建应用**

| 字段 | 说明 |
|---|---|
| 应用名称 | 如「花盆卫士 PC 客户端」 |
| 绑定产品 | **必须选第 1 步的产品**。这是「软件端应用 ↔ 后台上架商品」的唯一绑定点；激活时按它校验，绑错会返回 `403 PRODUCT_MISMATCH`。未绑定商品的产品不会出现在用户「我的空间」 |
| 状态 | 启用 |
| 最新版本号 | 客户端 `/app/version` 据此判断是否需要升级 |
| 离线宽限（天） | 断网可继续使用的天数，0 表示必须联网校验 |
| 安装包下载地址 | 客户端自更新下载用 |
| 更新说明 | 版本更新弹窗展示的文案 |
| 备注 | 内部备注 |

保存后弹窗显示 `app_key` / `app_secret`：

- **明文只显示这一次**，关掉后只能「重置密钥」重新生成
- 立刻写入软件端配置或密钥管理服务，不要硬编码进公开仓库

## 步骤 4 · 产生授权码

**正常路径（用户自助）**

```
用户扫码登录 → 官方商城下单 → 支付回调 → 自动创建授权 LIC-XXXXXXXX-XXXXXXXX-XXXXXXXX
```

授权与用户、产品绑定，含有效期与最大设备数，同时按规则在内部物联平台开户（对用户不可见）。

**测试路径（管理员手动）**

授权管理 → 「+ 发放授权」：

- 选用户 + 产品（**服务类商品不能发码** —— 额度包发的是 API 调用次数）
- 类型：永久 / 订阅 / 试用（非永久要填天数）
- 最大设备数：允许同时激活的机器数量
- 数量：1 = 单发；N = **批量发码**（最多 200 个，整批一个事务，生成后可一键复制）
- 立即返回 `license_key`

渠道、线下客户、OEM 一次要几十个码时走批量；发完在授权列表按用户/产品筛出来即可。

**卖实体卡 / 渠道铺货：走「卡密池」**

印卡时还不知道是谁用，所以发放弹窗里把「发放方式」切到 **卡密池（先发码，用户自己绑）**：

| 步骤 | 后台操作 | 结果 |
|---|---|---|
| 1. 印卡 | 发放方式 = 卡密池，填数量（≤200）、渠道、产品、时长 | 生成 `B2026xxxx-XXXX` 批次，码状态为「未绑定」 |
| 2. 分发 | 「批次」→ 复制未领码 / 导出 CSV 交给印刷厂或代理商 | 码不带用户、不带到期时间 |
| 3. 用户领取 | 用户在「我的授权 → 绑定授权码」贴码，或客服在列表点「绑定用户」 | 绑定那一刻才开始计时 |
| 4. 收尾 | 退货 / 印错：「批次」→「作废未领」 | 只作废没被领走的，已绑定的不受影响 |

要点：

- **卡密池的码在被绑定之前不能激活**，客户端会收到 `403 LICENSE_UNASSIGNED`，引导用户去绑定
- 有效期从**绑定那一刻**起算，不是印卡那天 —— 印了半年才卖出去的卡不会白亏半年
- 绑定是防枚举设计：别人的码和不存在的码，提示语完全一致
- 对账：「导出 CSV」按当前筛选（状态 / 批次 / 关键词）导出，带 BOM，Excel 直接打开

## 步骤 4.5 · 配置该产品专属套餐档位

**路径：产品运营 → 套餐档位 → 顶部下拉选中本应用 → 「从模板复制到该产品」**

每个软件产品有**自己的一套档位**，不能全站共用一套：`free` / `member` 这类 code 在不同产品下允许重复，但同一产品内唯一。绑定链路：

```
products(上架软件商品) ←— open_apps.product_id —→ open_apps.id ←— plans.app_id —→ plans.id
                                                        ↑
                                     licenses.app_id / licenses.plan_id
```

初始种子里的五档是 `app_id` 为空的**通用模板**，只作底稿、不直接售卖。新软件上架的标准动作：

1. 在「开放接口」建应用并绑定上架商品（步骤 3）
2. 在「套餐档位」顶部下拉选中该应用 → 点「从模板复制到该产品」，一次生成五档
3. 按实际价格 / 周期 / 权益逐档修改；也可「导出 JSON」存档、改完再「导入 JSON」。选中产品时导入会整份落到该产品，不会写回通用模板

| 档位 | code | tier | 计费 | 联网 | 离线宽限 | 设备 / 席位 |
|---|---|---|---|---|---|---|
| 在线免费版 | `free` | 0 | 免费 | 必须 | 0 | 1 / 1 |
| 在线会员版 | `member` | 10 | 周期订阅 | 必须 | ≤7 天 | 2 / 1 |
| 在线高级会员版 | `pro` | 20 | 周期订阅 | 必须 | ≤7 天 | 5 / 1 |
| 离线企业版 | `enterprise` | 30 | 周期订阅 | 可离线 | 90 天 | 10 / 10 |
| 离线企业分布式版 | `enterprise_dist` | 40 | 周期订阅 | 可离线 | 365 天 | 50 / 100 |

上表是模板占位值，**每个产品上线前都要按自己的价格 / 周期 / 权益改**。

**运行时以数据库为准**：`导出 JSON` 只用于备份和版本管理；`导入 JSON` 按 `(产品, code)` 新增或更新，不会删除已有档位，也不会改动已售出的授权（授权里存的是 `plan_code` 快照）。后台「开放接口」列表会显示每个应用已配的档位数，方便发现漏配。

字段要点：

- `tier` 决定升降级方向，只允许往更高档升级；不能降级
- `online_required=1` 的档位 `offline_days` 不能超过 7 天（短时断网宽限）；要长期离线请改用企业档
- `features` 是权限码数组，**随 Ed25519 离线票据一起签名下发**，客户端本地验签后据此开放功能；断网时问不了服务端
- `period_days` 决定续费延长多少天；免费档 `end_at` 为空，永不过期

**用户端「我的空间」**：只展示「应用已启用 + 绑定的商品已上架」的产品，每个产品一张卡片显示绑定的商品名、当前档位、授权码、到期日与已绑设备数，并直接提供「升级档位 / 续费」按钮（走普通下单支付）。升档与续费都**不发新码**，只原地改同一张授权，保留 `license_id` 与所有已绑定机器。下单时服务端校验档位与授权必须属于同一产品，跨产品升级会被拒。

**免费档自动发码**：用户注册时发一张「不限应用」的兜底码；进入「我的空间」或软件端扫码登录时，按产品补发该应用专属的免费档授权码（按 `user_id + app_id` 幂等）。因此每个产品都有独立、可单独升级的授权。套餐授权 `product_id=0`，激活时按 `licenses.app_id` 与档位 `app_id` 校验，A 软件的码不能在 B 软件里激活（返回 `403 PRODUCT_MISMATCH`）。升级前发出的历史通用码仍按「不限应用」放行，不锁死老客户。

**升级 / 续费都不发新码**：两者只改原授权的 `plan_code` / `max_devices` / `end_at`，保留 `license_id` 与所有已绑定机器。发新码会让老设备立刻被判 `MACHINE_NOT_BOUND`，用户升一次级就得重新激活。升级差价由服务端按剩余天数折算（设置项 `upgrade_proration`），前端传 `price` 一律不认；续费按 `max(原到期, 现在) + period_days` 延长，不会吃掉用户没用完的时长。

**到期前一键续费**：服务每 6 小时扫一次 `licenses.end_at`，按 `renew_remind_days`（默认 `7,3,1`）生成站内提醒，用户端「我的授权」顶部出现「一键续费」；「我的空间」产品卡片上也常驻续费入口。点它走普通下单支付，回调里延长有效期。一期**不接自动代扣**（微信委托代扣 / 支付宝商家扣款都需要单独申请权限，且对交易量与注册资本有门槛）。

**微信昵称与头像**：扫码登录默认取微信昵称 / 头像；服务号没返回头像（未关注时很常见）会按 openid 稳定分配一张**内置卡通头像**。用户在「账户中心」点选内置头像即可更换，无需填地址（图片链接作为高级选项保留），改过之后（`profile_custom=1`）微信重登不再覆盖。头像库里存 `preset:01` 短标识，对外接口一律展开成 data URI，软件端 `GET /user/profile` 直接 `<img src>` 就能显示、离线也有效；软件端也可用 `POST /user/profile` 修改，两边共用同一套校验。

## 步骤 5.5 · 代理商与佣金提现

**路径：用户 → 代理商与佣金（后台） / 我的收益（用户端）**

手动授权：后台输入用户 ID + 佣金比例（0~1）+ 邀请码，即把该用户设为代理商。名下用户有两条来源：后台手动指派，或用户拿邀请码在「我的收益」自助绑定；**归属一旦绑定不随订单漂移**。

计佣规则（都在 `server/lib/commission.js`）：

- 基数用 `orders.pay_amount` **实收**，不是标价，积分抵扣部分不计佣
- `UNIQUE(order_id, agent_user_id, kind)` 保证支付回调与「向微信查单」重复触发不会记两笔
- 账期 `agent_settle_days`（默认 T+7）：`pending → settled` 后才可提现，堵住「付款→提现→退款」的亏损链路
- 退款必须冲正；已提现后才退款的另记一条负数 `adjustment`，从后续可提现里扣
- 代理商自己下单不计佣；只做**一级**分销

用户中心「我的收益」展示待结算 / 可提现 / 已提现 / 累计与逐笔明细，提现按当前全部可提现余额整笔提交（最低额 `agent_withdraw_min`）。

**一期提现走人工审核 + 线下打款**：后台「代理商与佣金 → 提现单」点「已打款」或「驳回」（驳回会自动把锁定的佣金退回可提现），支持导出 CSV 对账。二期再接微信「商家转账到零钱」把打款自动化 —— 那个产品要单独申请转账场景（分销返佣 / 佣金报酬），审核会实际进系统看推广业务与计佣依据，且 2025-01-15 后单笔上限 200 元、需用户主动确认收款。给个人发佣金涉及个税代扣代缴，平台代收货款再分给个人还有「二清」风险，量起来后建议改走微信「分账」产品。

## 步骤 5 · 客户端激活并接入

接口前缀 `/api/open/v1`，应用级请求需 HMAC 签名头：
`X-App-Key` / `X-Timestamp` / `X-Nonce` / `X-Signature`。

```
1. 首次启动
   POST /auth/activate
   { "license_key": "LIC-XXXXXXXX-XXXXXXXX-XXXXXXXX", "machine_id": "<设备指纹>", "machine_name": "办公室PC", "version": "1.0.0" }
   → { access_token, refresh_token, license, user }

2. 每次启动
   GET /license/verify          (Bearer access_token)
   → { valid, license, expire_at }

3. 运行中保活（5~10 分钟一次）
   POST /license/heartbeat

4. 令牌续期
   POST /auth/refresh

5. 读硬件与设备凭据
   GET /user/devices
```

**machine_id 生成建议**：主板序列号 + CPU ID + 硬盘序列号 + MAC，做 SHA-256 后持久化。
不要用 IP、主机名、时间戳，否则重装系统或换网就占用新名额。

**离线宽限**：设了 `offline_days` 后，客户端连续离线超过该天数应拒绝启动，防止拔网绕过吊销。套餐授权以档位的 `offline_days` 为准；历史商品授权 / 卡密池码没有档位，仍用开放应用里的「离线宽限」。

**离线票据**（`POST /license/ticket`，Ed25519 签名）：payload 除 `iat` / `exp` / `machine_id` 外，现在还带 `plan_code` / `plan_name` / `tier` / `features` / `seats` / `online_required` / `offline_days`。客户端把公钥内置在安装包里做 pinning，验签通过后**本地**判断能开放哪些功能；`iat` / `exp` 双校验防改本机时间续命。`/app/version` 也会下发 `plan_catalog` 供展示档位，但真正的权益判断以票据签名字段为准。

**用户中心免登**：软件端 `POST /auth/handoff` 的 `to` 白名单新增 `earnings`，可直接把用户送到「我的收益」页。

## 步骤 6 · 上线后的日常维护

| 场景 | 去哪里 |
|---|---|
| 看有哪些客户端在线、踢单台下线 | 开放接口 → 会话 |
| 密钥泄露、换承包商 | 开放接口 → 重置密钥 |
| 暂停某产品的接入 | 开放接口 → 停用应用 |
| 用户续费、过期重开 | 用户端「我的授权 → 一键续费 / 升级」；后台「代理商与佣金 → 到期提醒」可手动扫描 |
| 用户换电脑 | 授权管理 → 点「设备数」→ 解绑；用户也可自己在用户端「我的授权 → 设备」里解绑 |
| 退款、违规 | 授权管理 → 吊销 |
| 看 API 调用量与额度 | blcloud 调用 / API 消费 |
| 发新版 | 开放接口 → 改「最新版本号 + 安装包地址 + 更新说明」 |

## 接入前自检清单

- [ ] 产品已建档、状态为上架、图标与简介齐全
- [ ] 官方上架里已设为推荐（需要在首页露出时）
- [ ] 开放应用已创建，**绑定产品正确**
- [ ] app_secret 已安全保存（明文只在创建时出现一次）
- [ ] 有至少一条测试授权码，且最大设备数 ≥ 1
- [ ] 客户端能走通 activate → verify → heartbeat 三步
- [ ] 断网场景验证过离线宽限行为（`/app/version` 的 `offline_days`）
- [ ] 验过解绑即时生效：解绑后用旧令牌请求应返回 401 `SESSION_REVOKED`
- [ ] 验过卡密池：印 5 张 → 用户绑定 1 张 → 有效期从绑定时刻起算（不是印卡时刻）
- [ ] 验过未绑定的码激活被拒：`403 LICENSE_UNASSIGNED`
- [ ] 验过离线票据：断网后功能仍可用到 `exp`，把系统时间往回拨会被判失效
- [ ] 验过超过 max_devices 时返回 409 `MACHINE_LIMIT` 而不是静默多绑
- [ ] 换机器、吊销、过期三种异常都有友好提示
- [ ] 开放应用已绑定正确的上架商品，且「套餐档位」已选中该应用复制/配置专属档位（不是共用通用模板）
- [ ] 每个产品的五档价格 / 周期 / 权益已按实际改好，并导出 JSON 存进版本库
- [ ] 用户「我的空间」能看到该产品、当前档位、授权码，且升级 / 续费按钮能下单支付
- [ ] 验过跨产品隔离：A 产品的授权码在 B 软件激活返回 `403 PRODUCT_MISMATCH`；B 产品的档位不能升 A 产品的授权
- [ ] 扫码登录后默认带出微信昵称与头像；微信没给头像时分配到卡通头像且重登不乱跳；账户中心可点选更换，软件端 `/user/profile` 拿到的 avatar 可直接 `<img src>`
- [ ] 新注册用户自动拿到免费档授权码，用它能走通 activate
- [ ] 验过升级与续费**不换授权码**：`license_id`、已绑定机器都保留，老设备无需重新激活
